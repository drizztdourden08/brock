The Controllers hub lists the pads that are plugged in when the app starts. The module's boot task now loads the device list and keeps listening to it, and loads it again when the diagnostics hold is restored, so a pad no longer needs a replug to show up. The diagnostics wizard has the look and wording of RotP's wizard again: the capture prompts, the input grid, the byte grid and the result lines are styled, and the intro, chooser and capture steps use their original text. The wizard runs inside Tessera's `Wizard` with its step strip and Back and Next bar, and keeps no header row of its own. The pad page has one Diagnose button instead of a diagnose icon and a report icon. It runs the diagnostics with that pad already chosen, so the wizard skips Choose a controller, and the last step hands the result to the registered Report action (the action with the id `report`) as `onSelect(entry, result)`. With no Report action registered the flow ends on its result step, and the Diagnostics page in the hub keeps its controller picker. `DeviceCardAction.onSelect` takes an optional second argument, and the module exports `REPORT_ACTION_ID` and the `DiagnosticsRunResult` type. The positional capture step now takes button presses: it used to wait for a first state event before it had a baseline, and SDL only reports a state when it changes, so an idle pad never answered. Auto-capture is on by default with a visible checkbox to turn it off.

The positional capture grid is laid out on equal rows with no wrapping, and each input shows one of three states: answered (success colour with a short pop), current (accent colour, pulsing, with a call banner that names the input to press or move) and pending. The animation stops under reduced motion. The Summary step shows the positional capture as a table.

The input module now adds a Controllers hub in place of the single input tester screen. The hub has the id `controllers` and sits under Advanced, outside the hub switcher. It holds a Directory page (a searchable table of every controller SDL3 knows, with Rescan), a Logs page (the connect and disconnect history) and a Diagnostics page (the guided capture wizard and its result). The pages come with the stick and trigger calibration wizards, the HID byte capture and the diagnostics report builder. The module exports `ControllerDirectory`, `ControllerLogs` and `ControllerDiagnostics`, plus `StepIndicator`, `ReportSection`, `buildReport`, `useDiagnosticsWizardState` and the other pieces an app needs to build its own report dialog around the wizard. `registerDeviceCardActions` keeps working, and is the hook an app uses to add a Report button. The peer range for `@drizztdourden08/tessera` is now `>=0.60.0`. `brock-build` adds `<id>.page.tsx` to the module file names its structure check accepts. Upgrading: `InputTester`, `DeviceCard`, `CalibrationPanel` and its types, `inputFamilyOf`, `inputTesterScreen` and `INPUT_TESTER_SCREEN_ID` are removed, and the `input-tester` screen is gone, so the Advanced entry now opens the `controllers` hub. An app that declares its own bucket with the id `controllers` fails at start. `brock upgrade` turns each import of a removed name, a `controllers` bucket in `screens.config.ts`, an `input-tester` id and an input module override with `screens: []` into a to-do (migration `controllers-bucket`).

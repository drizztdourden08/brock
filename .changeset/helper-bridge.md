Outside helpers and the bridge. `helpers` in `brock.config.ts` names standalone Node entries, such as a stdio MCP helper: `brock build` and `brock dev` bundle each into `dist/helpers/<name>.mjs` with only Node built-ins left as imports, refuse an Electron import, and the managed electron-builder config ships them in `resources/helpers` outside the asar. `bootstrapApp({ bridge: { register } })` opens an opt-in local bridge in main: a per-session named pipe on Windows or a 0600 Unix socket in a private temp folder, never TCP, guarded by a random per-session secret that never crosses the wire: an HMAC handshake proves both ends hold it, and each request carries an HMAC under a session key, with ids that must grow. The discovery file always lives in the per-user app data folder, keyed by instance, private to the user (0600, or an icacls entry for the user alone on Windows), cleared when stale and removed on quit. The client refuses a stale or open file, a dead pid, a non-local endpoint and, on POSIX, a socket folder that is not the user's own. Unauthenticated connections have their own cap and a 2 s deadline. Routes take a `validate` check, and handler errors are masked unless they are a `BridgeError`. Routes are `invoke` entries, as in the IPC contract. Messages are JSON lines with ids, bounded by `maxMessageBytes`. The helper's client is `connectBridge` from the new `@drizztdourden08/brock-electron/bridge` entry, which imports nothing from Electron. `helperLaunch(name)` gives the command, arguments and environment for an MCP client config.

The built-in review no longer fails on a loaded machine because a clock window ran out. Waits in the review now end on the signal they wait for: a change in the page, a layout that has stopped moving, a store change, or a window event from main for popped widget windows (new `review:windows` event). Each wait keeps one generous ceiling of 30 s, used only to fail a stuck check, and the failure now says what it waited for. This replaces the 3 s `waitFor`, the 8 s popped window wait, the fixed pauses before captures (settle, tour steps, performance samples, popped widget paint, widget options, the dev gate quiet period) and the 1 s capture prepare limit of the baseline run. The mascot still check counts frames instead of polling. The review idle watchdog now hears from every wait and step (new `review:alive` message), so only a silent step trips it, and its limit is 45 s. The review start limit follows boot progress: main tasks, the renderer boot, the page loading and each request the page finishes restart the 60 s silence window, so a first dev launch that is warming Vite no longer fails. A boot that makes no progress at all still stops at 60 s, and a hard ceiling of 5 minutes stays. The frame check of the review now reads the title of a bare cornerTitle window from `aria-labelledby` or the corner chip when the header and `aria-label` give none.

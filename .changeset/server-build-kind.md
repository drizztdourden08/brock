The server app kind builds. `server` is a new platform in `targets`: `targets: ['server']` is a windowless app, `['desktop', 'server']` ships both. `server.entry` in brock.config.ts names the entry, default `server/main.ts`. `brock server build` bundles it with Vite SSR into `dist/server/main.mjs`, one Node file with every dependency inlined, the app's `build.aliases` and `build.define` applied, and `brock server dev` rebuilds on change and restarts it with `node --watch`; anything after `--` reaches the app. The bundle refuses an `electron` import and a native `.node` addon (and the `bindings` and `node-gyp-build` loaders) with a clear error. The helper bundle now calls the same Node bundle config, and its output is unchanged. `brock build` builds the server for a server app and both builds for a desktop plus server app, and `brock build --if-stale` checks `dist/server/main.mjs` and the `server` folder. A windowless app gets none of the Electron or renderer managed files (electron.vite.config.ts, electron-builder.config.cjs, the boot, handler, review, screen, widget, title bar, tour and start-up lists, the palette and the module lists but the manifest) and none of the installer or screen checks; `brock dev` on it points at `brock server dev`. The managed tsconfig.json now includes `server`, so every app's tsconfig changes on its next `brock sync`. In thread, `serverTarget({ app, userData, states })` is a launch target: dev runs `brock server dev`, `--prod` runs `brock build --if-stale` then `node dist/server/main.mjs --user-data=<dir>`, output piped, and only the state `none` unless a states hook is given.

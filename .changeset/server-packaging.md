The server app kind packages. `brock server package [--arch x64,arm64] [--deb]` builds the server, then fills `release/server`: `<prefix>server-linux-<arch>.tar.gz` (the launcher `bin/<id>-server`, a pinned Node binary and `server/main.mjs`, under `<id>/`), a `docker/` build context made from the same tarballs, and with `--deb` a `<prefix>server_<version>_<arch>.deb`. The Node binary comes from nodejs.org, is checked against SHASUMS256.txt, and is cached in `~/.brock/cache/node`; a mismatch stops the build. `--deb` needs `dpkg-deb` and refuses with a clear message on a machine without it (`brock doctor` checks it on Linux). The tarball is written by Brock itself, so the modes are right when it is built on Windows. A server-only app runs the same command as `brock package`. New `server` options in brock.config.ts: `node` (exact Node version, default 24.11.0), `osPackages` (Debian names, the deb `Depends` and the Docker `apt-get install`), `ports` (EXPOSE and the unit description), `image` (default `ghcr.io/<repo owner>/<id>-server`) and `arch` (default `['x64']`; `--arch` overrides it). `brock sync` now keeps `build/server/<id>.service` (system user, `StateDirectory`, restart on failure), `build/server/Dockerfile` (Debian trixie-slim, non-root user, one `/data` volume, `HEALTHCHECK` running `<id>-server health`), `build/server/postinst` and `build/server/prerm`; an optional `build/server/after-install.sh` runs in postinst before the service starts.

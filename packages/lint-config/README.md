# brock-lint-config

Brock's app preset on top of [`@drizztdourden08/standards`](https://github.com/drizztdourden08/standards). The rules, the factories and the word lists live in standards; this package keeps the names Brock apps import, so an app config does not change.

## Use

```js
// eslint.config.mjs
import { brockEslint } from '@drizztdourden08/brock-lint-config';
export default brockEslint({ presets: ['react-app'], primitivesGlobs: ['src/ui/primitives/**/*.tsx'], allow: ['enhanced'] });

// stylelint.config.mjs
import { brockStylelint } from '@drizztdourden08/brock-lint-config/stylelint';
export default brockStylelint({ uiGlobs: ['src/**/*.css'], tokenGlobs: ['src/theme/**/*.css'] });

// .markdownlint-cli2.mjs
import { brockMarkdownlint } from '@drizztdourden08/brock-lint-config/markdownlint';
export default brockMarkdownlint({ ignores: ['vendor/**'] });
```

```json
{ "extends": "@drizztdourden08/brock-lint-config/tsconfig/react.json", "include": ["src"] }
```

## What it adds to standards

`brockEslint` is `standardsEslint` with the `react-app` preset and Brock's extension, `standards.extension.mjs`, which the package also declares in its `package.json`, so installing it is enough:

| Facet | Adds |
|---|---|
| ESLint | raw-control messages that name the Tessera components (`TextInput`, `Select`, `TextArea`), default exports for screen files, widget files (`src/widgets/**/<id>.widget.tsx`) and the widget layout (`src/widgets/layout.ts`), module entries, `brock.workspace.mjs` and `boot/*.task.ts`, and screen and widget files as lists for `local/one-export-per-file` |
| ESLint | `brock/data-only`, `brock/verbatim-source`, and the `@kind data` and `@kind verbatim` file kinds below |
| stylelint | `@drizztdourden08/tessera/tokens.css` as a token source for `brock/no-token-override` and `brock/no-token-shadow` |

## Allowing a word or an identifier

The writing rules (`local/no-slop-identifiers` and the prose rules) read one list of allowed words. Name a field that the rules would flag, such as `claudeId`, in either shape and `brockEslint` passes it on:

```js
export default brockEslint({ allow: ['claudeId'] });
export default brockEslint({ prose: { allow: ['claudeId'] } });
```

Both shapes join, so a repo may use them together. The same list can sit in `standards.config.mjs` as `options.allow` or `options.prose.allow`. The words reach `local/no-slop-identifiers` and the slop rules, and nothing else changes.

## Generated tool files

An app's `.gitignore` must not name tool files, so a worktree that a config generator provisioned holds `.ai-config.json`, `.mcp.json` and a generated `CLAUDE.md` that git does not ignore. `brockMarkdownlint` skips the generated markdown guides and `brock prose` skips the untracked root files (git lists them, so a file the app committed is still read). The list is `GENERATED_FILES` in `generated-files.constants.mjs`, and the `generated-files` export tells which of them exist in a folder. A guide counts as generated only when its first lines say `GENERATED by ai-config`, and `.ai-config.json` only when it names `ai-config/` as its `$generator`. A `CLAUDE.md` or `AGENTS.md` an app wrote itself has no such line and stays linted. `.mcp.json` carries no marker, so it is skipped by name.

## The data file kind

A record file or a generated table declares `@kind data` in its header (`/* @layer shared-game @kind data */`). `brockEslint` lists those files when it loads (from `git ls-files` under `rootDir`, else the current folder, or a walk outside git) and turns three rules off for them: `max-lines`, `local/one-export-per-file` and `local/constants-in-constants-file`. `brock/data-only` runs on every source file and, in a file with that header, fails on anything that is not data: a top-level statement other than an import, a type, an export list or a `const`, and inside a `const` anything other than literals, template literals, arrays, objects (no methods, getters or setters), spreads, references, unary and arithmetic or bitwise operators, `as`, `satisfies` and `Object.freeze`. So the exemptions cover data alone, and a file cannot claim the kind to dodge the rules. An editor picks a newly marked file up when its ESLint server restarts.

## The verbatim file kind

Some data files hold text reproduced word for word from an outside source, which the app must show exactly as it is: a licence text, a quoted dialogue table, the strings a protocol defines. The writing rules would flag that text, and rewording it would change what the app shows. Such a file declares `@kind verbatim` and names its source in the header:

```ts
/* @layer shared-legal @kind verbatim @source the licence text of the bundled font, from its OFL.txt */
```

A verbatim file is a data file: the three rules above are off for it and `brock/data-only` keeps it to data. `brockEslint` also passes each verbatim file to the standards factory as a `verbatimText` entry, with the source as its `why`, so `local/no-em-dash`, `local/no-smart-punctuation`, `local/no-slop-prose` and `local/no-tool-brand-words` run with `skipStringValues` there and skip its string literals and template text. Identifiers, comments and the header are still read by every rule. `brock/verbatim-source` fails a `@kind verbatim` header without `@source <text>`, and the string values are read until the header names one. An ordinary `@kind data` file keeps every prose rule, so UI strings never ride on the exemption. `brock structure` lists every verbatim file with its source, and a review sees what is exempt; `dataFiles(rootDir)` from `@drizztdourden08/brock-lint-config/data-files` returns the same list (`{ file, kind, source }` for each `@kind data` and `@kind verbatim` file).

The kinds are decided here and not in standards because standards decides file kinds from the path (`fileKinds`), and a core rule such as `max-lines` cannot read the header. Moving it into standards means a header-aware `kindsOf` there, which `local/one-export-per-file` and `local/constants-in-constants-file` would then read, and a `files` block like this one for `max-lines`.

Every option of the standards factories works here. The rules, their ids (`local/*`, `BROCK001` to `BROCK006`, `brock/no-token-*`) and the extension API are documented in the standards README; the structure guide is its `docs/structure.md`.

# Brock v0.102.0

Apps get context menus built from their commands, a settings page can show a preview beside its rows, and an app can draw one background behind every panel.

## New

- Add a context menu to any element or command zone. Spread `contextMenuZone(id)` on the element (no wrapper) and declare its entries with `useContextMenu(id, entries)`. Entries are command ids, separators, `{ command, label?, args? }`, `{ label, run }` or submenus two levels deep, and they show each command's label, icon, current shortcut and checked or disabled state. A right click opens the menu at the pointer, Shift+F10 or the Menu key opens it at the focused element, and a long press works on touch and pen. Text fields keep the browser menu unless the zone sets `typing: true`.
- Steer a context menu with `shouldOpen`, `beforeOpen`, `anchor`, `inherit` and `openOn`, and open, list or block menus from code with `openContextMenu`, `listContextMenus` and `blockContextMenus`. A command's `run` receives `{ point, target, trigger, data, args }`, and a command can report `checked`.
- Show a preview beside a settings page's rows with `preview` on the tab or page meta and `previewPlacement: 'start' | 'end'`. From 56rem wide it sits in a column that stays in view; narrower, it stacks above the rows.
- Draw one node behind the rail, toolbars, widget host, docked panels and main view with `background` on `BrockApp`. It takes no pointer events, though its children can opt back in.

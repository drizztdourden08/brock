# Brock v0.104.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- A handler registered through `ctx.handle` can throw an `AppError` (`new AppError(message, { code, data? })`) and the renderer reads the code and data back with `isAppError(error, 'code')`, where before only the message crossed. The error rejects as usual with the human message plus an encoded tail that the preload keeps and `isAppError` decodes. `data` must be JSON-safe (checked when the error is made) and is dropped with `dataDropped: true` past 8192 characters of JSON. A plain error behaves as before, and no stack crosses. `AppError`, `isAppError`, `toAppError`, `encodeAppError` and `decodeAppError` come from `@drizztdourden08/brock-core/ipc`.
- Add `product.menu.profiles`, true by default. With `false` the Profiles entry leaves the main menu, as `product.menu.home: false` does for Home. Profiles themselves keep working: the profile switcher, the command palette and the shortcuts are unchanged. The review does not expect the Profiles entry then. Add `product.initialProfile`, a profile name such as `Default`. On the first start, when no profile exists, the `profiles` boot task creates a profile with that name and activates it without opening the profile picker. The Profiles screen and switching stay available, unlike `singleProfile`. With a profile already on disk nothing changes.
- A first-run tour step can light three more shell parts with `target: { shell }`. `'page'` is the screen host alone, without the rail, the title bar or the docked widgets. `'rail'` is the screens rail. `'hero'` is the Home hero, or the hero of the open hub when Home has none. `'screen'` is unchanged. A part that is not on screen leaves the step centred, like any other missing part.
- A first-run tour step can light the page tab strip with `target: { shell: 'tabs' }`. A step also takes `openMenu`, which opens a title bar menu before the step lights its target and closes it when the step ends: `'menu'` is the app menu, and any other id is the title bar action menu with that id. A new target, `{ menuEntry: 'Take the tour' }`, lights the entry of an open menu by its label.

## Fixes

- An app test can import brock-react again. `@drizztdourden08/brock-build/vitest` exports `defineBrockVitestConfig`, which sets the automatic JSX runtime and compiles every `@drizztdourden08/*` package instead of loading it as is, and `brock sync` writes it as a managed `vitest.config.ts` for an app with a `test` script. A `vitest.config.ts` you wrote yourself is left alone; wrap it in the factory. Run `brock sync` after updating.
- Pad callouts prefer the sides over the area below the pad at small sizes. A callout below the pad now costs more the further it sits from its button, and a layout that grows past the card height pays for each extra pixel, so the pad shrinks to leave room at the sides instead of growing a tall frame with long leaders under it. The layout tries a few pad sizes and keeps the cheapest. View, Menu and Share still prefer a spot above the highest button, with View first, then Menu, then Share, and the best arrangement of those three is chosen before the other callouts are placed. A short search moves a few crowded callouts together when that lowers the total cost. Meta buttons low on the pad, such as the SNES Select and Start, keep their nearest spot.

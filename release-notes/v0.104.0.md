# Brock v0.104.0

Errors from main reach the renderer with their code and data, tours can point at more of the shell and inside menus, and apps can test brock-react under vitest.

## Upgrading

- Run `brock sync` in an app with a `test` script. It writes a managed `vitest.config.ts` built on `defineBrockVitestConfig` from `@drizztdourden08/brock-build/vitest`, which uses the automatic JSX runtime and transforms Brock's packages, so a test can import brock-react. A hand-written `vitest.config.ts` without the managed header is left alone; call `defineBrockVitestConfig(import.meta.dirname)` from it yourself.

## New

- Throw `new AppError(message, { code, data })` from a `ctx.handle` handler and test it in the renderer with `isAppError(error, code)`, which narrows to an error carrying `code` and `data`. Data must be JSON; above 8 KB it is dropped and `dataDropped` is set. A stack never crosses, and a plain error still carries only its message.
- Point a tour step at the `page`, `rail`, `hero` or `tabs` shell part. Open a title bar menu for a step with `openMenu` (`'menu'` for the app menu, or a title bar menu id) and light an entry inside it with the target `{ menuEntry: '<label>' }`.
- Hide the Profiles entry from the main menu with `product.menu.profiles: false`. Profiles keep working everywhere else.
- Create and switch to a first profile on first start with `product.initialProfile: '<name>'`, with no picker. The Profiles screen stays.

## Fixes

- Prefer side spots over below for pad callouts on a small window. A callout below the pad costs more the further it drops, a layout taller than the card costs more, and the pad shrinks to make side room. View, Menu and Share sit above the pad's highest button when there is room.

# Brock v0.106.1

`brock sync --check` now fails when the committed `guide.parts` file is stale, so a build no longer leaves a dirty tree behind a passing check.

## Upgrading

- Run `brock sync` once and commit the `guide.parts` file if the check names it.

## Fixes

- Check the committed `guide.parts` file in `brock sync --check`. The check runs `tessera guide`, compares the file it writes with the committed one, and names the file when they differ. CRLF against LF does not count. The committed file is put back after the check. Before, a stale file passed the check and `brock build` rewrote it, so every worktree was dirty after a build.

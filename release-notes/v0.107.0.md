# Brock v0.107.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- A process job now keeps its full output in a log file. The outcome of `ctx.processes.run` (and `jobs.runProcess`) gains `logFile`, the path of a file under the debug folder (`process-logs`) with every cleaned, redacted line of stdout and stderr, next to the 20-line `tail`, which stays as it is. The file is bounded at 5 MiB: it keeps the start and the end and marks the gap. The new `logFile` run option sets another cap (`logFile: { maxBytes }`) or turns the file off (`logFile: false`). `log: false` also writes no file. Brock keeps the newest 20 log files and removes older ones.
- Take the tour now sits at the top level of the app menu, just above Credits and About, in every app that has tours. It no longer hides under Advanced, or under Help when the app has a Help group, so new users and a first-run tour can find it at once. An app with several tours still lists them in a submenu of that entry. To upgrade, check your tour steps. A step that uses `menuEntry: ['Advanced', 'Take the tour']` no longer finds the entry. Use the plain `menuEntry: 'Take the tour'` instead.

## Fixes

- A dev start does less work twice. The renderer dependency crawl is kept in `node_modules/.vite/brock-renderer-deps.json` and reused while no file it read changed, which saves about 1 to 2 s on a warm start and more on a cold disk. `brock sync --if-stale` now copies the brand icons that changed, so `launch` runs one Brock process before the dev server instead of two and no longer redraws the Setup splash, which only `brock package` needs.

# Brock v0.107.0

Process jobs keep their full output in a log file, Take the tour moves to the top level of the app menu, and a dev start does less repeated work.

## Upgrading

- Change a tour step that points at `menuEntry: ['Advanced', 'Take the tour']` to `menuEntry: 'Take the tour'`. The old path no longer finds the entry.

## New

- Read a process job's whole output from `logFile` on the outcome of `ctx.processes.run` and `jobs.runProcess`. The file sits under the debug folder in `process-logs` and holds every cleaned, redacted line of stdout and stderr. The 20-line `tail` stays as it is. The file is capped at 5 MiB: it keeps the start and the end and marks the gap. Set another cap with the `logFile: { maxBytes }` run option, or turn the file off with `logFile: false`. A run with `log: false` writes no file either. Brock keeps the newest 20 log files.

## Changes

- Take the tour sits at the top level of the app menu, just above Credits and About, in every app that has tours. It no longer hides under Advanced or Help, so new users and a first-run tour find it at once. An app with several tours still lists them in a submenu of that entry.

## Fixes

- Do less work twice on a dev start. The renderer dependency crawl is kept in `node_modules/.vite/brock-renderer-deps.json` and reused while no file it read changed, which saves 1 to 2 s on a warm start. `brock sync --if-stale` copies the brand icons that changed, so `launch` runs one Brock process before the dev server instead of two and no longer redraws the Setup splash. Only `brock package` needs the splash.

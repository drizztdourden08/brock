# Brock v0.108.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- The renderer dev server pre-bundles the Brock packages an app links from outside its workspace, such as a Brock checkout linked with `link:`, so a dev start loads a few chunks instead of about 1,900 source files. A stamp of the files those packages carry goes into the optimizer hash, so a branch switch or an edit there re-bundles them on the next start. `build.optimizeDeps.liveBrock: true`, `brock dev --live-brock` or `BROCK_LIVE_BROCK=1` keeps them as source with hot reload.
- An elevated installer job (`elevate: 'installer'`) can now be cancelled by default, so its Cancel button works. Cancel tries the normal stop first and ignores a refusal. If the installer exits during a short wait (2 s, then a forced kill and 3 s more), the outcome is `cancelled`. If it is still running, the job stops waiting and ends as `detached` with "The installer keeps running on its own. Brock stopped waiting for it." The output streams and the log file are closed and the child no longer holds the app open. `cancellable: false` still turns cancel off. The `detached` status is now documented on `ProcessJobOutcome`.

## Fixes

- A dev app now stops at once when the interface fails to load, for example on a module error after a Tessera mismatch. The splash shows the error with Open logs, Retry and Quit instead of waiting 120 s for the watchdog. Launch, dev, build and start also stop with one clear line when the app's Tessera does not fit what brock-react needs, and brock doctor checks the same.
- A dev start skips work it did before. Main and preload are not bundled again while no module file they read, the config or the install changed (`node_modules/.vite/brock-build-reuse`), which saves 2 to 4 s on a warm start. A new worktree with the same lockfile copies the Vite dependency cache that another worktree made, from `~/.brock/cache/vite-deps`, so its first start skips the dependency optimizer. `launch` now runs the sync in its own process instead of a child, and the cold-start Tessera guide runs after the app is spawned instead of before. `brock sync --if-stale` on an app that is already in sync no longer loads the whole CLI or the app config: it checks a few file stamps and a record of the last brand icon copy, which takes well under a second. `brock sync`, `brock sync --check` and `brock build` behave as before.
- Build against Tessera 0.80. Its `tokens.css` is one flat pre-built file, so a dev start no longer waits on a chain of style imports. Apps can bump Tessera to 0.80 for the faster start; 0.78 still works.

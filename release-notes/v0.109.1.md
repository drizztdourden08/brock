# Brock v0.109.1

One paragraph for the people who use Brock: what this release changes for them.

## Fixes

- @drizztdourden08/brock-build@0.109.1
- @drizztdourden08/create-brock@0.109.1
- @drizztdourden08/brock-thread@0.109.1
- An app no longer piles up launch files in its user data folder. The bridge writes a `launch-bridge.data-<hash>.json` file for every `--user-data` profile it runs with, and nothing removed it when a throwaway profile was deleted. On start the bridge now removes, in the background, the launch files whose profile folder is gone, that no running instance uses and that are older than five minutes. Instance launch files and the plain `launch-bridge.json` are never touched. - @drizztdourden08/brock-core@0.109.1
- `brockEslint` no longer depends on the folder ESLint runs from. When `rootDir` is not passed, it is now the folder of the eslint.config file that called the factory, else the nearest folder at or above the current one that holds an eslint.config file, else the current folder. Before, running ESLint from a subfolder (`apps/web` under a root config) listed the data and verbatim files relative to that subfolder, so their globs did not match and `@kind verbatim` files were not recognised. A `rootDir` you pass still wins.
- A context label now shows as Tessera's `sublabel` instead of text added to the title. A Players widget bound to a context labelled Sunday run keeps the title Players and shows Sunday run after it as a muted label with its own ellipsis, in a docked, floating or popped widget. A clipped title shows in full in a tooltip. Upgrade: the Tessera peer range is now `>=0.82.0 <1`, since `sublabel` needs Tessera 0.82. - @drizztdourden08/brock-core@0.109.1
- @drizztdourden08/brock-port-kit@0.109.1

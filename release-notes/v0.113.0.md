# Brock v0.113.0

Commands can hide, hold a key and take arguments; widgets and toolbars follow the app's state and can be kept per workspace; widgets get typed drag and drop and scoped state; hubs get a header slot and sticky params. The built-in review now waits on real signals instead of a clock.

## Upgrading

- Handle the new `why` values of `commands.run`: `'hidden'` for a command whose `visible()` is false, and `'invalid'` for arguments that fail the command's schema. A switch over every `why` value needs both cases.
- Add `params: {}` to any `ShowContext` you build by hand. `ShowContext` has a new `params` field.
- Do not use the `scope:` prefix for your own ui view keys. Brock now reserves it for scoped state.

## New

- Hide a command where it does not apply with `CommandDef.visible()`. A hidden command does not fire and is left out of `commands.list()` (pass `{ includeHidden: true }` to keep it), the palette search and the menus; `commands.describe(id)` reports `visible: false`. `CommandDef.only` names the surface, so two commands on one chord with different `only` values no longer conflict, and the Keyboard page shows both meanings.
- Let menus read command gates. A `MenuItem.command` entry is disabled with the command's reason as its description and dropped when hidden; a context menu command entry does the same.
- Hold a key with `CommandDef.hold: { release, tapMs? }`. It runs on key down, ignores key repeat and calls `release` once on key up, a lost modifier, blur or a hidden window. `commands.heldModifiers()` reads the held modifiers for a pointer drag.
- Give a command arguments with `CommandDef.args`, a schema checked by `commands.run`. `commands.bind`, `unbind` and `bindings` tie a chord to fixed arguments, saved in the keymap setting. A menu command with a missing value opens a value picker in the palette. `palette.open({ query, scope })` and `palette.pick` open the palette from code, and context menus take a `selection` and open with `contextMenu.openAt(element, data)`.
- Show widgets and toolbars by rule. `defineWidget` takes `when` and `contexts`, and `defineToolbar` takes `when`; a toolbar whose rule fails is not drawn and the user's layout is not touched. `widgets.setTitle(id, text)` sets a dynamic title, `empty` draws a forced widget with no context, `prefs` adds widget settings shown both in the widget's options and in a Widgets tab of Settings, and `contextEntries(itemId)` adds toolbar item menu entries above Brock's.
- Keep a layout per workspace with `defineWorkspace`, `registerWorkspaces` and the `workspaces` facade. A workspace with a `when` rule turns on by itself, keeps its own widget and toolbar layout and has Reset; the Widgets menu gets a Workspace sub-menu. No saved data moves. `layout.focusMode(on)` hides every widget, toolbar and open kit and restores them.
- Drag typed payloads between widgets with `dnd.type`, `dnd.source` and `dnd.target` (or `useDragSource`, `useDropTarget`). It works between docked and floating widgets. A target that accepts `dnd.files` takes files dropped from the desktop; main checks each path with the folder grant rules and the app only sees the paths main returns.
- Keep state per project or document with `uiViews.scope(key)` and `useWidgetState(key, initial, { scope })`, capped at 200 names per scope and 50 scopes by default, oldest dropped first.
- Draw a hub header with `header: { render(ctx), actions?(ctx) }` on a bucket. List route params to keep with `params: ['subject']`: they survive page changes, Back and a restored session and appear as `ctx.params` in `when` rules. `nav: 'rail'` draws an icon rail, `ScreensConfig.aliases` maps old route names, deep links included, and the Settings entry reads the settings bucket title.
- Declare a long silent review step with `timeoutMs` on `defineReviewStep`, up to 30 minutes, so an install or engine setup needs no heartbeat.

## Fixes

- Stop the built-in review from failing on a loaded machine. Waits end on the signal they wait for (a page change, a settled layout, a store change, or a window event from main) and keep one 30 s ceiling that names what it waited for. The idle watchdog hears from every wait and step, so only a silent step trips it, and the start limit follows boot progress, so a first dev launch warming Vite no longer fails. A boot with no progress still stops at 60 s, under a 5 minute ceiling.
- Read the title of a bare cornerTitle window in the review from `aria-labelledby` or the corner chip.

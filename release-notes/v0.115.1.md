# Brock v0.115.1

`worktree remove` no longer risks deleting a registered worktree on Windows, and it handles upgrade throwaways and unlisted leftover folders.

## Upgrading

- Upgrade from 0.114.0 or 0.115.0 before you run `worktree remove` on Windows. Those versions compared worktree paths without normalising case and slashes, so a registered worktree could be taken for a leftover and deleted.

## Fixes

- Compare worktree paths by their real path, with forward slashes and, on Windows, ignoring case, before deciding a folder is a leftover. A worktree git lists is never deleted as a leftover.
- Show one plain line when Brock's own delete removes the folder, and git's error only if the removal fails.
- Delete the branch of an upgrade throwaway (`brock-<version>`, with only `Upgrade Brock to <version>` commits) even when it was never pushed. Other unmerged branches are still refused.
- Clear a leftover folder under the worktrees folder that git no longer lists with `worktree remove <path>`, without following links or touching anything outside it.

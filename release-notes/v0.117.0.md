# Brock v0.117.0

A new `mcp` module lets an outside agent drive a running Brock app over MCP, for development. `brock add` now works offline in localpkg mode, and the dev window no longer opens blank after a lockfile change.

## Upgrading

- `emsdkOf` no longer reports `activate`, and its host option no longer takes a `platform`. `ensure-wasm` builds the SDK environment in Node (`emsdkEnvOf`) and runs the build script as `node <script>` on every platform.

## New

- New `mcp` module (`brock add mcp`). An outside agent drives the running app over MCP through a stdio helper on the Brock bridge. Built-in tools take screenshots, click, type, press keys, scroll, list and open widgets, list and run commands, and read the visible UI. An app adds its own tools with `defineMcpTool`, in main (`getMcp(ctx).tools.register`) or in the renderer (`useMcpTools`).
- The config file is the only control for the `mcp` module. It is on in development and off in a packaged build unless `product.moduleOptions.mcp.packaged` is true.
- `nav.route()` in brock-react gives the full current route: screen, section and tab, or the base view when no screen is open.
- The core package adds `@drizztdourden08/brock-core/args` (`ArgSchema` and `validateArgs`, still re-exported by brock-react), the open `ModuleOptions` interface with `product.moduleOptions`, and `helpers` in the module manifest.
- In brock-electron, `ctx.bridge.extend` lets a module add bridge routes. `bridgeFileFor` and `waitCaptureHolds` are exported beside `captureFrame`.
- The build bundles a module's helpers to `dist/helpers/<name>.mjs`. A packaged build ships them, with the `RunAsNode` fuse, only when `moduleOptions[id].packaged` is true.
- The React package exports `jobStepper`. It turns a job snapshot into Stepper props, so a page can show a job's steps inline without the job dialog.

## Changes

- `brock dev` pre-bundles the renderer dependencies before it starts electron-vite. It prints a line when the pre-bundle starts, one every 15 seconds, and the count at the end. A failed pre-bundle only warns and leaves the work to the dev server.
- `launchAppForTest` and `assertLaunchable` refuse a dist older than the app's sources or its install, and say which input changed. Pass `allowStale: true` to skip only this check.

## Fixes

- `brock add` works in localpkg mode. A `@drizztdourden08/*` module or peer goes into `package.json` as `^<version>` from the localpkg index, then `pnpm install --no-frozen-lockfile` runs. Before, `pnpm add` failed with ECONNREFUSED on the guarded scope registry. A package missing from the index fails with a note to run `localpkg publish <producer>`.
- The generated ci.yml checks out the full history in the job that runs `test:pr`, which failed on a shallow checkout with "no default branch found". Run `brock sync` to take it.
- `brock lint` no longer fails with "No files matching" when an app starts during a lint. The short-lived electron-vite config bundle is left out, and a file that vanishes before ESLint reads it is skipped.
- A reused main or preload bundle no longer prints "Generated an empty chunk". A real empty chunk still warns.
- The wasm build no longer sources `emsdk_env.bat`, which from a Git Bash parent left PATH alone and failed with "emcc is not recognized".

# Brock v0.121.0

This release adds three modules (brock-msu for MSU-1 music, brock-game-info for a shared game info widget, and a much larger randomizer with Archipelago and Archipelia support), the `brock apworld` commands, a cheats widget shell and the aspect ratio control. The input module gains the ControlsSettings view, controller overlays and a narrowed main context. Two randomizer changes remove or move exports, listed below, so check them before you upgrade.

## Changes

- New command `brock apworld build` packs an Archipelago world from a game's JSON export, with a generic Python loader shipped in `templates/apworld`, so a game builds an apworld with no Python of its own. See `docs/apworld.md`.
- New commands `brock apworld export`, `brock apworld refresh` and `brock apworld player-file`. Export loads the game's TypeScript entry and writes the six JSON files, `refresh` rebuilds the apworld only when a source is newer, and player-file writes a player yaml from a game function. See `docs/apworld.md`.
- The windowsHide check now comes from standards 0.15.0 as `local/spawn-hides-window`. brock-lint-config drops its own `brock/spawn-hides-window` and needs standards 0.15.0 or later. A consumer bumps `@drizztdourden08/standards` to `^0.15.0`. An exception that named `brock/spawn-hides-window` now names `local/spawn-hides-window`.
- New brock-core subpath `util` with the shared `mulberry32` and `itemAt`. The msu, input and randomizer modules now import them from core instead of keeping their own copies.
- The randomizer session survives a paused core. Roll may be async and gets a RollContext. The world takes a WorldStamp. A poll.loaded hook asks for a rebaseline. registerRandomizerGame starts the runtime. Option defs carry choices, sections and hints, and a game options body gets the step props. A new ./memory subpath ships. Port-kit sessions take prepareAssets. Profile build hooks may be async. The isDisabled function gets the composed lock cause, and useLockCauseOf reads it.
- Module profile hooks reach the main profile store. `composeProfileHooks` merges a list of hooks, and `MainModule.profileHooks` lets a module add its own.
- Brock React exports logRowsToText, the copy text of a log panel. The input module uses it in place of its own copy.
- Wizard step bodies get `onSubStepChange`. The randomizer options panel tab strip works while the wizard passes `subStep`, and reports each pick so the stepper can follow.
- Renderer modules can add profile modes, profile wizard steps, ordered settings lock causes and profile store hooks. `BrockApp` merges them with the app's own `profileModes`, `settings.lockCauses` and `profileHooks`.
- New cheats widget shell: `CheatsFrame` (a tab frame where a game passes its tabs as id, label and content), `ChoicePopover`, `NumberSetter`, `ControlLegend`, `PointerHintProvider` and `usePointerHintTarget`.
- The show flags store is exported, so a module can rerender when a flag changes.
- A wizard step body takes an optional subStep, the id of the sub-step the shell has selected, so a body can follow it.
- `defineWidgetGates` builds the `widgetDisabled` hook of `BrockApp` from a table of gates. Each widget id lists whether it reads game data and which setting it requires. A widget that reads game data is disabled while the `gameDataBlockedBy` setting is on, and a widget with a required setting is disabled while that setting is off. The app words the reason with `messageOf` and maps a setting to its route with `targetOf`. `resolveWidgetGate` is the pure step and the `WidgetGate` types are exported.
- `AspectRatioControl` takes `disabled` and `lockedMessage`. When disabled, every segmented control and the custom ratio inputs are disabled, and the locked message shows under the header.
- Adds an aspect ratio control and its ratio math. The `./aspect-ratio` export holds the pure math (clamp and reduce, nice ratio, custom ratio check, screen and viewport detection), and the renderer exports `AspectRatioControl`, which takes the presets, the limits, a letterbox flag, the value and an onChange.
- `CheatsShell` is the frame of a cheats widget with no game in it: a tab bar, the active tab remembered per widget, and a gate that shows a reason in place of the tabs while cheats are off. The game passes its tabs as `{ id, label, render }` and the shell draws only the active one. `CheatsShell` and `CHEATS_WIDGET_ID` are exported from `./renderer`. The block kind `described` is a game state section: rows with a label, a value, an optional tone and badge, and a description that opens when the label is clicked. The game supplies the rows as data, so a game info section can carry its game state with no game in the module.
- New module brock-game-info: one game info widget shared by every game. The game supplies a provider (a snapshot reader, a section list, its core and lock signals) and the module polls, diffs and draws it.
- Controls settings: generic profile extension field, verbs and group column headers, optional slots hint label, and the reserved rows render first.
- The module now ships a ControlsSettings view with profiles, devices and binding tabs driven by a game config. The renderer entry exports the view and the types of its game config and store ports.
- ControlsGame takes listenerExtra: the host renders its own content under the hint of the waiting-for-input popover. ListenTarget, ListenerExtraContext and BindingCapture are exported from the renderer.
- The main side takes a narrowed context, InputMainContext: handle, emit, files, paths, log, product and the two flags isHeadlessLaunch and hasFlag. A host that builds its own Electron main can call getInput and inputMain.register without a cast.
- The renderer entry gains the in-game controller overlays: ControllerPauseLayer (manual pause and controller disconnect), ProfileSwitcherOverlay, and the controller hooks wiring with a report host and boot task factory. Glyphs, the pause source and the report dialog are passed in by the app.
- The input renderer exports ControllerReportDialog, the guided controller report dialog. Pass it to ControllerReportHost through renderDialog. The app injects the reporter identity, the debug text and a submit function, so the dialog holds no product name or endpoint. The filed report type now carries an optional recordUrl in place of sanctuaryUrl, with a recordLinkLabel prop for its button. Rumble tests and the report device card action were already exported.
- New `@drizztdourden08/brock-msu/format` entry exposes the MSU-1 format constants (`MSU1_MAGIC_TEXT`, `MSU1_HEADER_BYTES`, `MSU1_SAMPLE_RATE`, `MSU1_CHANNELS`, `MSU1_BYTES_PER_FRAME`) and `msu1FrameCount`.
- New module brock-msu, the shared MSU-1 and MSU-L music module. The game supplies its track loops, music classifier, sound channels and save paths through `defineMsuGame`, and the core calls through an `MsuHost`.
- The MSU module gains its host side and the first part of its studio UI. A new `msu` IPC namespace carries `.msul` reading, the optimize measure and convert run with progress events, and the audio probe. The main entry holds the handlers and the ffmpeg tool definition, and the renderer entry holds `defineMsuStudio`, `MsuStudioProvider`, the music debugger widget, file audition and `useMsulOpen`. The renderer also exposes `createMsuStore(game, deps)`, the pack store behind the studio, and `useMsuStudio()`, which returns the game and the store.
- The audio adapter takes an optional target `sampleRate` and `channels`. Its own AudioContext opens at that rate and each pushed block is resampled (linear) and remixed to it first. Session options `audioSampleRate` and `audioChannels` pass them through.
- New `LocationBanner` renderer component: a fading banner over the game that names the place the player entered. A game passes the current `location` and a `locationNameOf` function that returns the place name or null.
- The port kit renderer exports MobileShell, useMobileBack and isMobileHost: the Android options drawer, opened by the back gesture, with the title and logo taken from the product config.
- The frame loop gains setSchedule with a display mode (the default, paced by the display) and a timer mode (a drift-corrected 60 Hz timer). The audio adapter takes an options object with leadS, how far ahead of the audio clock samples are queued, and the port session passes it through as audioLeadS. Omitting both keeps today's behaviour.
- Add createSpriteStore and spriteBaseUrl to port-kit, a manifest driven store for extracted sprites served through a product scheme. The randomizer renderer now exports defaultOptionTabs.
- A port session takes a schedule option, 'display' or 'timer', for its frame loop at start. PortSession.setSchedule switches the live loop, so a V-Sync toggle applies without a restart.
- The Archipelago network status gains the items sent to other players, hint points, the reconnect attempt and next retry time, the ping mean and sample count, and the tracker link progress of each player. Tracker links now follow the connection: a drop closes them and resets the roster, a reconnect reopens them, and a player's online state reads null until the server says otherwise. A received item from a negative location now names the server as its sender. A drop now closes the tracker links before the roster resets, so the roster asks again after the reconnect. A location scout lost to a drop is sent again on the next connect. The roster no longer sends '!players', so connecting no longer echoes it in every player's chat; online reads null until a Join, Part or tracker link says otherwise.
- The randomizer module now carries the Archipelia lobby client, the lobby socket and the Archipelago world export. A game plugs in through the new `ArchipelagoGame.archipelia` hook and plain inputs to the export functions. New `./preload` subpath exposes `window.api.randomizer` with the lobby socket and the save-files call.
- The Connection step of the profile wizard now shows for any mode that has an entry in `views.connection`. An entry is either a body component, as before, or a `ConnectionView`: `{ Body, validate?, summary? }`. Both hooks get the connection slice values and the wizard values. The online mode keeps its server fields, its checks and its summary when the game gives no entry for it. The review lists the connection of a custom mode with its summary. `game.roll` now runs for every mode except online. `RollContext` carries the `mode` and the `connection` values of the wizard, as an opaque record the game reads. The wizard passes them on `CreateProfileOptions.randomizerConnection`, and other callers can pass them the same way. `roll` may return `joinedRoll(result)`, a `RollJoined` (`{ kind: 'joined', result }`), in place of a placement. No placement is written then. `game.onJoined(result, { profileId, config })` runs once the profile is created. A roll that returns a placement works as before. `isJoinedRoll` tells the two apart.
- The randomizer module exports generic Archipelago adapter defaults (`idAdaptersOf`, `isFromServer`, `receivedOrderBySender`, `substituteForeign`) and the generic `deliverServerItem`, so a game no longer copies them.
- New `./archipelago` subpath with the Archipelago client types, plus `RandomizerGame.archipelago`, the online mode and its connection fields.
- The checks tracker is generalized. A game fills it through optional `TrackerProvider` hooks: `artOf`, `facets`, `facetsOf`, `kindOf`, `badgesOf` and `statusesOf`, and `TrackerGrouping` takes a `description`. The checks view gains summary counts, status, kind and tag filters, and compact, detailed and card layouts. It shows a placeholder when `artOf` returns null. The spoiler page uses the same view. A game that sets the new optional `inventory` provider (`InventoryProvider`, layouts of areas, rows and tiered slots) gets an inventory widget. A game without it carries no inventory widget.
- A game connection body now gets the connection record as its value, and its patches go to that record. The renderer entry exports CONNECTION_SLICE, the wizard key of that record.
- `GameWorldDef` takes an optional `seedValues(request)` hook. Its values fill `world.seedValues`, so rules can read seed nodes and the exported apworld answers them through `pre_rolled`.
- `views.optionsStep` and `views.optionSubSteps` are removed. Use `views.optionTabs` and `views.optionsAside`.
- A randomizer game can list extra wizard modes with an id, a label and a rank through the new `modes` field.
- The module now carries the launch connect and LAN discovery glue. The main entry adds `createRandomizerMain({ mdns })` with the LAN handlers (beacon listener, optional injected mDNS browser, firewall status and allow) and `launchRendererFlags(argv)`. The preload bridge adds `lan`. The renderer entry adds `launchConnect`, `launchesConnection` and `awaitLaunchConnection`, driven by a `LaunchConnectHost` the game supplies. The `--ap-connect` and `--lobby-join` parsers are exported from the archipelago entry.
- The archipelago entry exports openLobbyLink with its LobbyLink and LobbyLinkHandlers types, and the renderer entry exports the JoinFormOptions and JoinOutcome types of joinFromForm.
- The randomizer module now ships the Archipelia lobby setup and the profile fields. `LobbySetup` and its draft helpers (`useLanServers`, `useBrowsedLobbies`, `useLobbyCheck`, `useNetworkAccess`) read the module's own lobby client and LAN bridge. `ArchipeliaConnection` is a ready connection body: a game registers it under `views.connection` for its lobby mode. `lobbyConnectionFieldsOf`, `lobbyRowChip`, `buildLobbyFacts`, `lobbyStatusLine` and `randomizerFactsOf` build the saved fields, the row chip and the profile facts.
- The randomizer log passes a line id (autoStart, armed, rerollFailed) as a third argument, so a game's own log can route those lines to another channel.
- Games can word the boot log lines through the optional `logText` on the game contract, and the boot gate result now carries the raw `detail` of a block.
- Randomizer game modes take an optional when rule, and the wizard falls back to local when the chosen mode is hidden.
- Add the randomizer module with its world model, seeded rng and schema checks.
- The randomizer module provides the online notice settings (`isNoticeKindShown`, `ONLINE_NOTICE_DEFAULTS`, `noticeSettingKey`), the online settings rows (`onlineSettingsSections`), and the `ArchipelagoFiles` view with its `ArchipelagoFilesSlot` run panel, which saves the player yaml and the world package to a picked folder.
- The default options tab now renders each option as a row with a tag, a description, a control that follows the option kind and an optional pool impact cell, grouped by option group, with an Upcoming tab for options not yet implemented. OptionDef gains kind, range, group, description, details and implementation, and the renderer exports RandomizerOptionRow, OptionGroupList, OptionTabBody, UpcomingTabBody, PoolImpactCell and SpriteTileSet.
- The options step and the Options page now share one options panel with a tab per section (or per `views.optionTabs` entry), a changed count on each tab and an optional `views.optionsAside`. A tab can bring its own `Body`. `views.connection[mode]` replaces the connection step body for a mode. `RollContext` gains `onProgress`, surfaced as `useRollProgress`. New exports `useOptionTab` and `randomizerReviewSections` serve an app's own wizard review. `views.optionsStep` and `views.optionSubSteps` are deprecated in favour of `optionTabs`.
- RandomizerTypeRegistry takes an options slot, like frozenSettings. A game that sets it gets its own type for RandomizerProfileConfig.options; without it the type stays `Record<string, unknown>`.
- `addRandomizerPages` entries can carry a route, an order and a `when` predicate, and an entry whose key is a built-in page id (run, options, network, online, logs, spoiler) replaces that page in place.
- The Run page is a dashboard grid: Summary, Progress, Recent activity, Players, Settings, then the game's run panels with their spans. A game run panel may be a plain component or a RunPanelDef with an id, title, span and Body. The Network page uses the same grid. The Logs page classifies entries with generic activity kinds, then the game's logRules. Labels gain counters, events and kinds. The dashboard building blocks (DashboardCard, StatTiles, tallyTile, sessionToneOf, formatTime) are exported from the renderer.
- Add the randomizer game contract, profile types, session and memory types, main profile hooks and the game registry.
- The `./session` export is main-process safe again. `createLocalSessionFactory`, `createOnlineSessionFactory`, `useSessionStore`, `startSession`, `stopActiveSession`, `currentRun`, `readPlacement`, `writePlacement`, `gateRandomizerBoot`, `startSessionRuntime` and `appRandomizerLog` reached `@drizztdourden08/brock-react`, so they now come from `@drizztdourden08/brock-randomizer/renderer`.
- New `@drizztdourden08/brock-randomizer/test-kit` entry with the Archipelago test helpers a game's tests import: the fake server, the protocol harness with its fake core, and the apworld oracle rig, spoiler parser and forward replay.
- The randomizer renderer gains the tracker and run UI that apps used to write themselves. `CheckToasts` announces a check found and an online room notice, and reads the registered game's tracker. `DeliveryQueueIndicator` lists the items waiting to be delivered, fed by the delivery queue through `useDeliveryQueue`. `ProfileRandomizerTab` shows a run's seed, type and connection facts and its options, changed or all, with the shared option rows. The core entry exports `randomSeed`, which returns 16 hex characters from the platform crypto. The wizard review summary is already covered by `randomizerReviewSections`.
- New `./tracker` subpath with the tracker provider contract and its types, plus the `tracker`, `Checks` and `checksWidget` slots on the randomizer game.
- Run panels take an actions slot, and run panels and option tabs now receive the mode and the ROM file name. The options aside shows as an extra tab on narrow panels, and a game's log rules now match before the default ones.
- The inventory and checks widget slots now also set padding, icon and popOut, through one shared `WidgetSlot` type. The inventory widget shows a notice above the grid when the tracker has an `artOf` and no slot has art, with the text taken from `inventory.missingArtNotice`.
- The world kit now covers collection state, reachable regions, event sweeps, location checks and rule compile with a K-typed helper registry.
- Add `createWorldKit<K>()`, which returns the rule builders, combinators, `always`, `never` and the main fill phase bound to one set of world keys.
- The randomizer module now ships a generic Archipelago world model. worldModelOf takes a fill world, the option values and a set of hooks the game passes in, and returns the model the apworld loader reads. preRolledOf wraps it as the pre-rolled block. plainOptionValue and snapshotOfPlainOptions turn plain player-file values into option values against a game's option catalog.
- A SpriteTileItem takes an optional badge number, shown at the top right of its tile, for a pick order. A tile without a sprite shows the item's name instead of an empty image.
- The tools module now records and encodes. A RecordingButton and useRecordingCapture hook sample frames and send them to the main process, which encodes a video when ffmpeg is installed, with an FfmpegInstallStep and FfmpegRequiredDialog for the install. Wrap the bug report transport with withSentTagging to stamp sent recordings with sentAt.

## Fixes

- With `build.nodePolyfills` on, the renderer and web builds alias `vite-plugin-node-polyfills/shims/buffer`, `/process` and `/global` to the copy the app resolves. The plugin injects those imports into every file that uses Buffer, process or global, and a workspace package outside the app could not resolve them under pnpm.
- `composeProfileHooks` no longer seeds the merged profile extension with an empty object, so an app that augments `ProfileExtension` with required keys typechecks.
- Profile store hooks now build a partial slice of the profile extension, so a module hook no longer has to return the fields an app adds.
- Hidden windows restore a saved fullscreen state in headless mode.
- Opening a widget that is a hidden tab in a tab group now brings that tab to the front.
- The built-in Logs and Performance widgets are now `devOnly`, so they show only while developer tools are on.
- Module wizard steps typed on their own slice now fit the module list.
- The review tour gives each step the current app state. A fresh --review run now sees the devOnly entries that the profile step turns on.
- AspectRatioControl puts the label and the mode track on one line, with the preset picker and the custom pair right-aligned below.
- The Android library build now stages its CMake folder in the system temp folder by default on Windows, to stay under the 250 character object path limit; set `brockInputCmakeDir=project` to keep it in the package.
- The controller report dialog hides Open on GitHub and the issue link when the report has no issue URL, as with a clipboard submit.
- The MSU renderer now has a default export so the host can load it. MsuStudioPage, MsuStudioProvider and createMsuStore accept any game built with defineMsuStudio, whatever its Ctx and Target.
- The audio adapter now writes the audio context state, sample rate, sink, base latency and gain to the session log. It logs at the first samples, on every state change and once a minute. When the browser suspends or interrupts the context, the adapter resumes it, unless the game paused the audio on purpose.
- A slot that has DeathLink off now turns the DeathLink tag off, even when the connection asked for it. A refused session now disarms the game.
- The world subpath no longer loads the profile augment, so a game that declares its own randomizer profile field can import it.
- The run summary reads option entries without a cast, so apps that augment the options type with a plain interface typecheck.

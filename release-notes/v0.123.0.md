# Brock v0.123.0

This release brings translation to Brock apps. The new `brock-i18n` module stores the app and profile language, follows the system language and adds a Language settings tab. Every visible string in Brock, its modules and the Tessera parts can now come from a locale table, and switching the language needs no reload. Brock ships English only: an app adds its own tables, Brock's namespaces included. The release also moves to Tessera 0.132. A few helper signatures change and are listed under Upgrading.

## New

- `@drizztdourden08/brock-core/i18n` is the translation runtime: an ICU message parser, a translator with fallback chains and lazy locales, `msg()` and a `Messages` key augmentation. `AppState.locale` holds the active language, and `formatBytes` takes a `locale` option.
- The `brock-i18n` module stores the app language and a per profile language, detects the system language, exposes `window.api.i18n`, takes a `--lang` switch and adds a Language settings tab. `MainModule` gains a `beforeReady(ctx)` hook that runs before the app is ready, and `offeredLocales()` from `brock-electron/main` lists the tags the app ships.
- The renderer binding: `I18nProvider`, `useT`, `useText`, `useLocale`, `Trans` and a `locales` prop on `BrockApp`. Modules ship `messages` and can read the language per profile. The page gets `lang` and `dir`. `I18nProvider` takes `document={false}` so a nested provider leaves the page alone. With no locales and no i18n module the app stays in English.
- Main process text goes through `ctx.i18n`. The tray, the edit menu, the dialogs, the boot labels and the splash come from `brock-main.json`, and a language change rebuilds them. `bootstrapApp` takes `locales`.
- `brock sync` writes the locale files from `src/locales/<tag>/<namespace>.json` and from installed modules: `.brock/locales.ts`, one lazy chunk per other language, `.brock/locales.main.ts` and the typed `.brock/messages.type.ts`. The keys of package tables are typed too. `brock check` reports drift, `brock structure` checks the locale folders, and electron-builder ships only the offered languages.
- The `brock i18n` verb has check, coverage, add, todo, merge and tessera-base. `brock gate` runs the locale check when `src/locales` exists.
- The Tessera bridge translates Tessera's strings, function strings included, and passes the app language through `TesseraOverrides.locale`.
- The new lint rule `brock/no-literal-text` is off by default. It reports literal visible text in JSX, text attributes and label properties, so an app that translates can turn it on with one `extra` entry. The lint-config README shows how.
- The blank app template ships its own English table, `src/locales/en/app.json`, and wires the generated locales into `BrockApp` and the main bootstrap.
- `bin/ensure-addon.mjs --strict` exits 1 unless the SDL3 addon is current, so a packaging step stops on a stale or missing addon. `ensureAddon` and `addonReady` are exported from `@drizztdourden08/brock-input/ensure-addon`.

## Changes

- Visible def fields take `Text`, a plain string or a `msg()` ref: menu items, settings defs, screen, hub, bucket and tab titles, search seeds, tours, commands, dialog and toast options, title bar items, the tray, boot task labels, widget and job titles, legal text and data domain labels. Plain strings render as before.
- A job line is a `Text`. `JobHandle.step`, `progress`, `line` and `done` take a string or a `msg` key with values, and an asset step report takes a `Text` for its line.
- The input, display, updater, tools, catalog, secrets, msu and randomizer modules ship their strings in their own namespaces. The context menu label, the mascot search hint (`product.mascot.searchHint`) and the update dialog take `Text`.
- The randomizer wizard steps, tracker groupings, activity kinds, run, network, lobby, checks and logs views take `Text`. The Archipelago world export stays English.
- The clipboard backend picks the API the running Electron has: the sync calls up to Electron 44, and the async clipboard from 45.
- `brock sync` no longer lowers a Brock range that is above `brock.version`. It keeps the range and warns with the `brock upgrade` command that moves it. `followBrockPin` takes `{ keepAhead: true }`.
- Every boot line on the main terminal starts with a clock stamp, every boot step prints as a `[boot]` line, and the app log mirrors warn and error entries to the main terminal.
- The README says how an app translates the Brock namespaces in its own tables.

## Upgrading

- Brock builds on Tessera 0.132, and the brock-react peer range asks for Tessera 0.132 or later. Raise the Tessera range in your app.
- `formatKeyCode`, `formatKeyBinding`, `getBindingLabel` and `newProfile` in brock-input take a `text` function. Pass `useText()` in a component.
- The randomizer profile tab helpers take a trailing `text` resolver: `lobbyRowsOf`, `lobbyRowChip`, `lobbyStatusLine`, `buildLobbyFacts`, `randomizerFactsOf`, `runFactsOf`, `changedTextOf`, `formatPing`, `formatLastPacket` and `counterTilesOf`. `RandomizerLabels.counters` is `Record<string, Text>`.
- `placeWizardSteps` takes a `text` resolver as its third argument. Pass `useText()` so wizard step labels show in the active language.
- A field that now takes `Text` may hold a `msg()` ref. Code that reads one of these fields as a string resolves it with `useText()` first.

## Fixes

- With `build.nodePolyfills` on, the dev server pre-bundles the polyfill shims, so the page no longer reloads mid-boot.
- In development, an app window that sends no boot progress for 8 s is reloaded once.
- The clipboard watch never starts a poll while the previous one is still reading.
- Worktree and upgrade installs pass `--config.confirm-modules-purge=false`, so an install with no terminal no longer stops when it must recreate `node_modules`.

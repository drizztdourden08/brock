# Brock v0.123.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- `brock sync` writes the locale files from `src/locales/<tag>/<namespace>.json` and the `brock.locales` of installed modules: `.brock/locales.ts`, one lazy chunk per other language, `.brock/locales.main.ts` and the typed `.brock/messages.type.ts`. `brock check` reports drift, `brock structure` checks the locale folders, the `i18n` module id is registered, the screens literal reader accepts `msg('ns:key')` for tour titles, and electron-builder ships only the offered languages.
- New `brock i18n` verb with check, coverage, add, todo, merge and tessera-base, and `brock gate` runs the locale check when `src/locales` exists.
- Main process text goes through `ctx.i18n`. Brock's own English (tray, edit menu, dialogs, boot labels, splash) lives in `brock-main.json` and shows with no locales option. `bootstrapApp` takes `locales`, and a locale change rebuilds the tray, the edit menu and the splash text.
- Add the `@drizztdourden08/brock-core/i18n` runtime: an ICU message parser, a translator with fallback chains and lazy locales, `msg()`, a `Messages` key augmentation, `AppState.locale`, and a `locale` option for `formatBytes`.
- User-facing def fields take `Text`, a plain string or a `msg()` ref: menu items, settings defs, screen titles, tours, commands, dialog and toast options, the tray and boot task labels. Plain strings render as before.
- Title bar items and actions, legalText, data domain labels and boot report details take Text, and the region, title bar, About and storage words move to the brock-shell and brock-main catalogs.
- The context menu command label and default name, the mascot search hint and the update dialog texts take a `Text`, so apps can translate them. `product.mascot.searchHint` is a `Text`.
- A job line is a `Text`. `JobHandle.step`, `progress`, `line` and `done` take a string or a `msg` key with values, and `JobSnapshot.line` carries it. The job dialog, the catalog install bar and the MSU import form show it in the active language.
- An asset step report takes a `Text` for its line, so `report.line(msg('ns:key'))` shows in the active language. Brock React typechecks when the app's generated messages type narrows the keys: `isMessageKey` narrows the tour and Tessera keys read at run time.
- The clipboard backend runs on the async clipboard of Electron 45 and on Electron 38 to 44. It picks the API the running Electron has: the sync calls up to 44, and `clipboard.read`, `clipboard.write` and `ClipboardItem` from 45. The clipboard watch never starts a poll while the previous one is still reading.
- New `brock-i18n` module: the stored app and profile language, system detection, `window.api.i18n`, the `--lang` switch and a Language settings tab. `MainModule` gains a `beforeReady(ctx)` hook that runs before the app is ready, and `offeredLocales()` from `brock-electron/main` lists the tags the app ships.
- New rule `brock/no-literal-text`, off by default. It reports literal user-visible text in JSX text, text attributes and label properties, so an app that translates its text can turn it on with one `extra` entry and keep every string in the locale table. Options: `attributes`, `properties` and `ignore`. The lint-config README shows how to turn it on.
- Screens, hubs, the search index and the palette take `Text`. Bucket, group, hub and tab titles, hub actions, search seeds and settings groups are resolved where they are drawn, and the palette strings live in the English tables. The build keeps `{ key }` for a `msg()` title in the search seeds, and the runtime catalog resolves it in the active language.
- The Report a bug palette action, the randomizer wizard steps and their option sub-steps, the activity kind labels, the Checks view, the Run activity card and the Logs view take a `Text`, so apps can translate them. A profile wizard step's `label`, `description`, `summary` and `subSteps` labels are `Text` (`ProfileWizardSubStep` is exported), and `placeWizardSteps` takes a `text` resolver as its third argument. `TrackerGrouping.label` and `description`, and `RandomizerLabels.kinds`, are `Text`.
- `I18nProvider` takes `document={false}` to leave the page `lang` and `dir` alone, so a nested provider for another language no longer overwrites the app's.
- Renderer i18n binding: `I18nProvider`, `useT`, `useText`, `useLocale`, `Trans`, a `locales` prop on `BrockApp`, module `messages` and `i18n` locale source (per profile capable), translated Tessera strings, and `lang` and `dir` on the document. With no locales and no i18n module the app stays in English.
- The Tessera bridge translates function strings too. A `tessera` message such as `table.rowsOf` receives the named params of that string. The app locale now also reaches Tessera through `TesseraOverrides.locale`.
- The tools, catalog, secrets and msu modules ship their strings as message keys in their own namespaces. `ToolDef.installHint`, `ToolState.hint` and the catalog install bar text are `Text`. Tessera object entries such as `anchor.names` and `toolbars.sides` render one key per sub-key and are read back the same way.
- The input, display and updater modules ship their strings as `input:*`, `display:*` and `updater:*` message keys. In input, `DeviceCardAction.label` and `RumbleTest.label` are `Text`, and `formatKeyCode`, `formatKeyBinding`, `getBindingLabel` and `newProfile` take a `text` function.
- `bin/ensure-addon.mjs --strict` exits 1 unless the SDL3 addon is current, installed or built, so a packaging step stops on a stale or missing addon. `ensureAddon` and `addonReady` are exported from `@drizztdourden08/brock-input/ensure-addon`.
- The randomizer module has its own `randomizer` translation namespace. Option tab, option label, hint, description and choice labels, the options aside label, run panel titles, the missing art notice, tracker badges, assumptions and facet labels, the Archipelago start check, and the page, bucket, mode and widget labels are all `Text` and are resolved where they are drawn. `ChecksWidgetViews` and the inventory slot take an optional `label`. `ProfileModeDef.label` is a `Text`. The Archipelago world export stays English: `ApOptionDef.displayName` and `description` take `Text` and are written as plain strings.
- The randomizer module's remaining visible English text takes `Text` and lives in `locales/en/randomizer.json`: the run view, the network view and pill, the lobby setup, the profile tab facts, the wizard step, the connection fields and the extra pages empty message. The facts and row helpers of the profile tab take a trailing `text` resolver, `RandomizerLabels.counters` is `Record<string, Text>`, and `LiveMeta.empty` accepts a `Text`.

## Fixes

- With `build.nodePolyfills` on, the dev server now pre-bundles the polyfill shims the app resolves, so the page no longer reloads mid-boot.
- Screens, hubs, the search index and the palette take `Text`. Bucket, group, hub and tab titles, hub actions, search seeds and settings groups are resolved where they are drawn, and the palette strings live in the English tables. The build keeps `{ key }` for a `msg()` title in the search seeds, and the runtime catalog resolves it in the active language.
- The tools, catalog, secrets and msu modules ship their strings as message keys in their own namespaces. `ToolDef.installHint`, `ToolState.hint` and the catalog install bar text are `Text`. Tessera object entries such as `anchor.names` and `toolbars.sides` render one key per sub-key and are read back the same way.
- brock sync now types the keys of package text tables. React, Electron and the i18n module declare their locale folder, so `msg('brock-app:...')`, `msg('brock-main:...')` and `msg('i18n:...')` pass the `keyof Messages` check in an app. An app table that overrides a package key gives one member, not two. The package base tables still load from the packages, so the bundle does not change.
- `brock sync` no longer lowers a Brock range that is above `brock.version`. It keeps the range and warns that the pin is behind, with the `brock upgrade` command that moves it. `brock upgrade` still moves every range to its target, a downgrade included. `followBrockPin` takes `{ keepAhead: true }` for this and returns the kept fields as `ahead`.
- Main always prints every boot step to stdout as a `[boot]` line, including each main and renderer task with its duration.
- Widget, widget kit, kit overlay, kit requirement and job titles now accept message references and resolve them where they are shown.
- The app log arms the global error handlers when the bus is created and mirrors every warn and error entry to the main process terminal.
- The blank app template ships its own English table, src/locales/en/app.json, and passes the generated locales to BrockApp and to the main bootstrap. Its screens, settings, tour and widgets take their text through msg and useT.
- Every boot sequence line on the main terminal starts with a wall-clock stamp, HH:MM:SS.mmm, and `clockStamp` is exported.
- In development, an app window that loaded but sent no boot progress for 8 s is reloaded once.
- The randomizer module has its own `randomizer` translation namespace. Option tab, option label, hint, description and choice labels, the options aside label, run panel titles, the missing art notice, tracker badges, assumptions and facet labels, the Archipelago start check, and the page, bucket, mode and widget labels are all `Text` and are resolved where they are drawn. `ChecksWidgetViews` and the inventory slot take an optional `label`. `ProfileModeDef.label` is a `Text`. The Archipelago world export stays English: `ApOptionDef.displayName` and `description` take `Text` and are written as plain strings.
- The context menu command label and default name, the mascot search hint and the update dialog texts take a `Text`, so apps can translate them. `product.mascot.searchHint` is a `Text`.
- The randomizer module's remaining visible English text takes `Text` and lives in `locales/en/randomizer.json`: the run view, the network view and pill, the lobby setup, the profile tab facts, the wizard step, the connection fields and the extra pages empty message. The facts and row helpers of the profile tab take a trailing `text` resolver, `RandomizerLabels.counters` is `Record<string, Text>`, and `LiveMeta.empty` accepts a `Text`.
- Brock now builds on Tessera 0.132. The brock-react peer range asks for Tessera 0.132 or later, since the locale and key name strings come from it.
- An asset step report takes a `Text` for its line, so `report.line(msg('ns:key'))` shows in the active language. Brock React typechecks when the app's generated messages type narrows the keys: `isMessageKey` narrows the tour and Tessera keys read at run time.
- Worktree and upgrade installs pass `--config.confirm-modules-purge=false`. The old camelCase key was ignored by pnpm, so an install with no terminal still stopped on ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY when it had to recreate node_modules. - @drizztdourden08/build-cache@0.123.0
- The input, display and updater modules ship their strings as `input:*`, `display:*` and `updater:*` message keys. In input, `DeviceCardAction.label` and `RumbleTest.label` are `Text`, and `formatKeyCode`, `formatKeyBinding`, `getBindingLabel` and `newProfile` take a `text` function.
- The README says how an app translates the Brock namespaces in its own tables, since Brock ships English only.

# Brock v0.36.0

Brock now covers an app's side websites, Android controllers and display, screenshot baselines and a release note for every version, and it can adopt an app that was never on Brock. Everything an app gets stays general: nothing in Brock names one product.

## New

- A side website for an app: `brock site add <name>` creates a separate web app in the same repo, on Tessera, with the site header and footer, a sign-in page on the brand gradient, its own dev port and an `/api` dev proxy. Brock provides no server, sign-in or hosting code.
- Release notes for every version: each release needs `release-notes/v<version>.md`, the release workflow refuses to run without it, and the update dialog shows it as formatted text.
- Screenshot baselines in the review: `--review-bless` stores the captures, `--review-baselines` fails on any changed pixel and writes a diff image for each failure.
- New modules: `brock-tools` (download, verify and run an external program such as ffmpeg) and `brock-catalog` (browse, install, verify and remove content packs, with install links).
- Links and files open the app: `product.protocols`, link schemes and file types, registered by the installer on each platform and delivered to `ctx.onOpen`.
- The bug report can go through the app's own transport instead of a GitHub issue.
- App checks: `gate.scripts` adds an app's own checks to the gate, CI and upgrades; `gate.clangFormat` formats and checks C files.
- Dev-only screens and handler groups (`.dev` in the file name) that never reach a release build.
- `<app> linux push` builds and installs the Linux version on a test machine.

## Platforms

- The input and display modules work on Android with the same API as the desktop: controllers, rumble and the display's refresh rate.
- CI and release workflows for a repo with several apps: each app gets its own CI, run only when a change touches it, and its own release.

## Under the hood

- Tessera 0.30: Escape closes one layer at a time, failed screens and widgets show the shared error look with Retry and Details, and the menus and resize handles are Tessera's.
- Each app loads only its own brand's colour palette.
- Branch tools remember each working copy's own base branch, so a long-running integration branch works like main.
- `brock adopt` takes in an app that was never on Brock; `brock migrate --tessera-from-copy --map <file>` converts an app's own copy of the design system to Tessera.
- Build options for workers, Node polyfills and extra aliases; a data file kind for large data records.

## Upgrading

- Run `<app> upgrade`. It adds the release-notes folder, the palette import and the new managed workflows. Write `release-notes/v<version>.md` before your next release.
- Apps that used the SNES plugin's built-in ROM list or launch flags now set their own in `brock.workspace.mjs`.

## Fixes

- Two saves of the same file at once no longer fail, and a half-finished build no longer shows a blank window.
- Dev-only files stay out of release builds when the app sits behind a link or a short path name.
- The review job uploads its report from the right folder in a repo with several apps.

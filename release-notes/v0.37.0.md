# Brock v0.37.0

The release workflows now hold up on a real first release: Linux packages build, a failed build leaves no tag behind, the workflows reach git, and CI runs on every push to main. Menus open toward the side with room.

## Changes

- Every menu with a button opens toward the side with room, from Tessera 0.31.
- `launch --prod` rebuilds first when the sources are newer than the build, through the new `brock build --if-stale`.
- An upgrade runs the full gate, as CI does: frozen install, `brock check`, lint, typecheck, markdown, structure, tests and the app's own gate steps.

## Platforms

- Linux packages build with the app's icon and the metadata the `.deb` needs (homepage, maintainer and description from the product).
- `brock package` copies the brand icons on every platform and stops if the icon for that platform is missing.

## Under the hood

- The managed workflows run on Node 24 actions, CI also runs on a push to the default branch, and the review job stays on Ubuntu 24.04.
- The pnpm version comes from `packageManager` alone, which adopt and create-brock now write.

## Upgrading

- Run `<app> upgrade`. Two migrations add `!.github/` to `.gitignore`, so the workflows are committed, and the `packageManager` field. Then commit the updated workflows.

## Fixes

- A failed release build leaves no tag and no version commit behind, so the same version can run again. The version is committed and tagged only after every build succeeded.
- `.github` is no longer hidden by the standard ignore rule, and `brock check` fails while a managed workflow is untracked.
- The production review loads its small fixtures, which a production build had turned into blocked inline URLs.

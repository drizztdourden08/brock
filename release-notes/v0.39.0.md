# Brock v0.39.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- An app adds its own steps to the managed CI and release workflows in `brock.config.ts`, `workflows.steps`, so `brock sync`, `brock build` and `platform add` keep them. Steps go in at fixed points: `ci.beforeInstall`, `ci.beforeBuild`, `ci.afterBuild` and `ci.beforeTest`, and `release.beforeInstall`, `release.beforePackage` and `release.afterPackage` (a file copied into `upload/` there ships with the release). A step takes `run` or `uses` (with `with`), `env`, `if`, `shell`, the repository `secrets` it reads (each set as an environment variable of the step), and `os` and `platforms` to keep it to some runners or platform jobs. Modules (`brock.workflows` in their manifest) and the repo command's plugins (`definePlugin({ workflows })`) add steps the same way, before the app's. `workflows: { ci: 'own' }` or `{ release: 'own' }` leaves that file to the app: `brock sync` stops writing it and `brock check` stops comparing it.
- `build.define` in `brock.config.ts` replaces globals at build time in main, preload, the renderer, its workers and the web build. Each value is a JSON value, written into the code as it is in the config.
- `packaging` in `brock.config.ts` adds to the managed electron-builder config and to `vpk pack`: `extraResources` from the app folder, an `afterPack` module of the app that runs after Brock's own hook, a macOS `role` and an `icon` per file association, and `velopackIcons` for the icon `vpk pack` takes on Windows and Linux.
- In a repo of several apps the shared workspace `ci.yml` runs the steps of every app, in workspace order, each named `<app>: <step>`, a shell step with `working-directory` and `APP_DIR` set to its app, and the plugins' steps once. `workflows: { ci: 'own' }` in `brock.workspace.mjs` leaves that shared file to the repo; an app's own `workflows` setting covers only its own files. A `uses` step of the same action, version and inputs runs once per job, however many apps or modules declare it.
- `brock.site.ts` takes `tsconfig.compilerOptions`, merged over the managed site `tsconfig.json`, and `build.define`. The managed site tsconfig allows `.ts` imports, so `brock.site.ts` can read its port offsets from a constant the repo shares, such as `import { TOOL_PORTS } from '../../ports.constants.ts'`.
- `tsconfig.compilerOptions` in `brock.config.ts` merges over the managed `tsconfig.json`, key by key, with `paths` merged entry by entry, so an app can turn an option off while it fixes its errors without a hand edit that `brock check` would flag. Without it the managed file is unchanged.
- The bug report takes a contact email and attachments. A renderer or main transport opts in with `contact: true` and `attachments: true | { maxFiles?, maxBytes? }`; the dialog then shows a Contact email field and a drop zone for files, capped at 5 files and 10 MB in all by default. The payload carries `contact` and `attachments` (`{ name, type, size, data }`), never into a public GitHub issue, and `writeDebugZip` stores each attachment under `attachments/` with only its name, type and size in `report.json`.
- Renderer extras reach the bug report transport. `useBugReportExtras(source)` or `bugReport.setExtras(source)` registers a function that returns a JSON-safe object; the dialog calls it when it opens and the payload carries the answer as `extras`, so a main transport (`bootstrapApp({ bugReport })`) gets what only the renderer knows, such as the open screen. A source that throws leaves `extras` out and the report still goes.
- `FileStore` has an optional `trash(path)`. The Node store behind `ctx.files` moves the path to the system trash (`shell.trashItem`) and skips one that is not there. A catalog uninstall or update hands its installer a store whose `remove` goes to the trash when the store has one, falling back to deleting when the trash refuses; `removeTo: 'delete'` in the catalog config deletes as before.
- The bug report falls back to a GitHub issue when the main transport cannot send. A main transport can declare `available(ctx)`; while it answers false, the dialog targets the prefilled issue on `product.repo` (else the clipboard) from the start. When a transport fails on send and the product has a `repo`, the error offers Open a GitHub issue instead, which opens the issue with the same title, text and diagnostics.
- `JobHandle.setCancellable(on)` turns cancel off (or back on) while a job runs; the snapshot's `cancellable` follows, so the job dialog hides Cancel and `jobs.cancel` is ignored. A catalog install and a tool install turn it off once the download is in, before the checks and the unpack, and `installBarProps` leaves out `onCancel` then, so `CatalogInstallBar` shows no Cancel past the download.
- A module settings tab no longer clashes with an app settings page or tab of the same id. The app keeps the plain id and the module tab moves to `<moduleId>.<tabId>` (`moduleTabId`), as does a module tab whose id an earlier module tab took. A module tab nothing else claims keeps its id, so existing links to it still open it. `mergeModules` now records `moduleId` on each module tab.
- Tessera 0.32: an outside press and Escape dismiss anchored parts, a hint that follows the pointer, disabled tabs with a reason, a held Disclosure, ListDetailLayout by share with a detail side that folds, and LogPanel row selection.
- App code can tell an item is installing without its own copy of the job id: `CATALOG_JOB_PREFIX`, `catalogJobId(itemId)` and `isCatalogInstalling(itemId, jobs)` come from every entry of the catalog module. `jobs` is a job list (the renderer's job store, `ctx.jobs.list()`) or anything with a `list()`, such as `ctx.jobs`.
- `readInstalledRecords(source)` from `@drizztdourden08/brock-catalog/main` reads `catalog/installed.json` with no main context, for a boot task, a test or another process. `source` is a `FileStore` rooted at `Data/`, the `Data/` folder itself, or the path of the JSON file; a missing or damaged file reads as no records.
- The display settings defaults now depend on the host. `displayDefaultsFor(host)` merges `DEFAULT_DISPLAY_SETTINGS` with `HOST_DISPLAY_DEFAULTS`, which turns `syncedRateInFullscreen` on for Android, where the app is always full screen; the desktop and the web keep it off. `readDisplaySettings(settings, host?)` reads a missing key as the host default. Spread `displayDefaultsFor(detectHost())` into the app's defaults to store the same value.
- `BROCK_INPUT_CMAKE_DIR` puts the CMake build folders of an addon source build at a short path (a folder, or `temp` for the system temp folder), one subfolder per package copy, so a build deep in a worktree stays under the Windows path length limit. The Android library build reads the same variable, or `brockInputCmakeDir` in `mobile/android/gradle.properties`, for its CMake staging folder.
- Apps can add their own buttons to the input module's device cards. `registerDeviceCardActions(actions)` (or the `useDeviceCardActions` hook) adds them to every card, the module's Controllers screen included, and `InputTester` (`deviceActions`) and `DeviceCard` (`actions`, now exported) take them as a prop too. Each `DeviceCardAction` has an `id`, a `label`, an optional `icon` and `variant`, `disabled` and `visible` checks on the `DeviceEntry`, and `onSelect(entry)`.
- `inputApi()` no longer returns null. On a host with no input side it returns `noopInputApi`, which reports controllers off, lists nothing, refuses every action and hands back an unsubscribe for every subscription, so app code needs no null check. `isInputAvailable()` tells whether a real input host is there. Existing `inputApi()?.` calls keep working; they can drop the `?.`.
- `runAssetWorkerJob(ctx, options)` (port-kit `/main`) runs an app's asset extraction steps in a worker thread as a `ctx.job`, with each step's progress, lines and log on the job and cancel ending the thread; the worker module serves its steps with `serveAssetSteps` from the new `/worker` entry.
- The core's crash watch takes `crashArmDelayMs` (a runtime error that soon after a start is swallowed) and `onCrash({ message, error, event })` in `createGameCore` options, and reports only the first crash of a run.
- ensure-wasm activates the Emscripten SDK on Windows through its `emsdk_env.bat` before the build script, and `skipWithoutSdk` (or `--skip-without-sdk`) skips a stale build when no SDK is found, resolving `'skipped'`; `emsdkOf` reports what it found.
- Named saves rename, overwrite, prune and size: `rename` and `overwrite` keep the id, `prune` removes past the newest `keep` or older than `maxAgeMs`, `details` and `size` count each save's bytes, an entry carries an optional `meta`, and `createSaveStore(files, { companions })` removes a slot's companion files whenever it is written or removed.
- `createLiveSettings({ calls, apply })` and `createSramSync({ read, store, profileId })` run without `createGameCore`, for an app that loads its core itself; `createCoreCalls(module)` is exported to build the calls of an Emscripten module.
- `createGameCore(port, { precompiled })` instantiates a `WebAssembly.Module` the app compiled ahead (or a function resolving one) instead of fetching and compiling the core at each start; `compileCore(port)` compiles the core for such a warm-up.
- The ROM store takes unknown dumps (`acceptUnknown`: stored under their SHA-1 and flagged `unknown` with their `hash`), zips (the single known dump inside, or with `acceptUnknown` a lone ROM file; any other zip is refused with a `message` listing what it held), a `maxBytes` limit and several ROM kinds (`rom.kinds`, each with its own known list, file rules and folder, through `store.of(kind)`); `remove` also deletes what the kind's `derived(file, files)` names and resolves the removed paths.
- Save transform hooks: `createSaveSlots({ transform })` and `createPortSession({ saveTransform })` take `save(state, kind)`, which may be async, to change the core's state bytes before they are stored, and `load(state)` to change them back before the core loads them.
- `useSignIn` starts signed in when a token is stored. A sign-in provider names the secret its token goes to with `tokenSecret`, or answers itself with `isSignedIn()`; `window.api.secrets.signIn.signedIn()` returns each provider's state, and the module's renderer boot task reads it before the window shows, so a screen no longer draws the signed-out state first. `useSignInStore` adds `loaded` and `loadSignedIn()`.
- A tool installed while the app runs is found. `getTools` reads the PATH on each lookup (at most every 2 s): on Windows the process PATH merged with the saved machine and user PATH from the registry, elsewhere the process PATH. `ToolsEnv.pathEnv` takes a string or a function. Main sends `tools:changed` after an install (`window.api.tools.onChanged`), and `useTool(id, { refreshOnFocus? })` locates the tool again on that event and whenever the window gets focus (on by default), beside its `refresh()`.
- A registered tool can carry a `probe` and an `aroundRun` hook. `probe: { binary?, args?, timeoutMs?, read? }` runs the found binary (`--version` by default) and reads the result; the default reader passes on exit code 0 and takes the first dotted number as the version. `probe` can also be a function of the found paths. A copy that fails its probe counts as not found, so the lookup moves on to the next folder, and a passing one puts its `version` on `ToolState` and `ToolLocation`. A result is kept until the binary's size or time changes. `aroundRun(call, next)` wraps every run of the tool, the probe included, and may change the call or the result. `systemPath()` and `readVersion` are exported.
- The updater measures the installed app. `window.api.updater.installSize()` returns its size on disk in bytes (the Velopack install folder on Windows, the `.app` bundle on macOS, the AppImage on Linux), or `null` outside an install. On Windows the module also writes it to the app's uninstall entry as a `REG_DWORD` `EstimatedSize`, the only type Windows Settings reads, so Installed apps shows the app's size; it never creates the key. `createUpdaterMain({ installSize: false })` turns the write off.
- The updater hides itself on a host that cannot update itself. On a platform whose `capabilities.selfUpdate` is false (the web build, Android), or without the module's preload bridge, there is no Check for updates menu entry, no title bar action and no update dialog. `useUpdateAction` returns `null` there, and `useSelfUpdateHost()` and `selfUpdateHost(capabilities?)` are exported for app code.
- The update dialog has a notice slot for the app. `setUpdateNotice(notice)` from `@drizztdourden08/brock-updater/renderer` takes a map from version to content, or a function that gets `{ version, currentVersion, action, prerelease }` for the version the user picked and returns content or nothing. The dialog shows it above the release notes, a string as a warning callout. It returns the undo.

## Fixes

- The managed electron-builder config puts `author` (`{ name, email }` from `product.author`) into `extraMetadata` beside `homepage`, so an app's `package.json` need not repeat it.
- A main or preload chunk with an import line inside a template literal builds as written: electron-vite put its CommonJS shim inside the literal, and Brock now moves it after the last import statement. `brock check` fails, and `brock sync` warns, while the app's `package.json` lacks `"type": "module"`, which the managed configs need for `import.meta.dirname`.
- Every Linux job of the managed workflows runs on `ubuntu-24.04`, never `ubuntu-latest`, which moves to Ubuntu 26 on 19 October 2026: the CI `changes`, `quality` and `web` jobs, the workspace and site CI jobs, and the release `prepare`, `build-linux` (the `.deb` and the AppImage), `build-android`, `build-web` and `release` jobs, as the review job already did.
- The managed release workflow moves the repo's `base` branch (from `brock.workspace.mjs`, else `main`) to the release commit, where it moved GitHub's default branch before, so a repo that releases from an integration branch keeps its version bump there.
- `brock site add`, `brock sync` and `brock check` warn when a site's `src` or `public` holds a folder named like its dev proxy path (`src/api` under `/api`), whose files the proxy would send to the API and leave the page blank.
- `brock site add` names a site's views after the site (`StoreShell`, `StoreHome` and `StoreSignIn` for `apps/store`), so two sites in one repo pass Tessera's duplicate-part check. Existing sites keep their views.
- Dev-only screen files (`inspector.page.dev.tsx`, `state.tab.dev.tsx`, `tools.settings.dev.ts` and the other dev-only kinds) lint as screen files: their default export and their `meta` export pass, as in the shipped screen files.
- `appOpen` hands a held launch request to every handler that subscribes before the next task, not only the first. A file or link the app was launched with used to reach one screen when two screens subscribed in the same render; now each gets it, and a handler that subscribes later does not see it again.
- The step table of `.brock/upgrade-report.md` lists every gate step the upgrade runs, `brock check` and `lint:md` included: a step after a failed one shows as not run, where the table stopped at the failure before.
- `JobHandle.setCancellable(on)` turns cancel off (or back on) while a job runs; the snapshot's `cancellable` follows, so the job dialog hides Cancel and `jobs.cancel` is ignored. A catalog install and a tool install turn it off once the download is in, before the checks and the unpack, and `installBarProps` leaves out `onCancel` then, so `CatalogInstallBar` shows no Cancel past the download.

# Brock v0.40.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- A bug report transport can keep the dialog open after a report went out. `afterSend: 'view'` beside `contact` and `attachments` (in `BrockApp`'s `bugReport` or in `bootstrapApp`'s) shows the receipt in the dialog in place of the form: the message, the report id, Open when the receipt has a `url`, and Close. The default, `'toast'`, closes the dialog and raises the toast as before; the GitHub issue and the clipboard always toast.
- A Capacitor host. On Android or iOS brock-react fell back to the web factory: no file store, `formFactor: 'desktop'`, no title bar, and `ports.capacitor` of a module was never read. It now builds a `capacitor` platform over the app's Capacitor plugins (Filesystem, App, Haptics, KeepAwake, by name): the app's files persist in the app data folder, the device port drives the back button, pause and haptics, `formFactor` is `mobile`, and module ports for `capacitor` are merged in. A new capability, `titleBar`, draws the title bar with its menu on a phone, while `windowChrome` keeps the window buttons to Electron; it is optional on `Capabilities` and reads as true when a custom platform factory leaves it out, so existing factories keep their bar. ui-views persist through the Capacitor file store, so they survive a restart on the phone.
- Three main-side hooks for app data and sound. `bootstrapApp({ fileGuard })` is asked before each write of the base `file:*` handlers (`writeBytes`, `writeText`, `remove`, `mkdir`, `trash`) with `{ kind, path }`, and refuses the write when it answers `false` or a reason. `FileStore.trash(path)` now reaches the renderer too (`file:trash`, the Electron `files` port). `createNodeFileStore({ trashItem })` takes the function that moves a full path to the trash, so the store imports no Electron; `ctx.files` passes Electron's `shell.trashItem`, and a store made without `trashItem` has no `trash`. `window:setAudioMuted` and `window:isAudioMuted` mute the app window and read it back, also as the window port's optional `setAudioMuted` and `isAudioMuted`.
- `--screenshot` waits until the app is ready to be pictured, and pictures the current frame. The renderer takes a hold with `holdScreenshot()` (or `useScreenshotHold(holding)`) while something it draws is not ready, such as a game view before its first frame; main waits for the reveal and then for every hold to be released, within the same 20 s watchdog. The capture now comes from the window's surface through the debugger (`Page.captureScreenshot`), since `capturePage` returned a stale frame for the headless window placed off every monitor; it falls back to `capturePage` when the debugger is taken.
- `ui-views.json` is written by key. Brock read the file once and wrote its whole copy back on every change, so a key the app wrote to the same file in the meantime was lost. The renderer now sends only the keys it changed over the new `uiViews:patch` channel (`patchUiViews`), and main merges them into the file on disk, one write after another. An app keeps view state of its own there with `uiViews.read(key, fallback)`, `uiViews.write(key, value)` and `uiViews.remove(key)` from brock-react; the `profile:` keys stay Brock's.
- `@drizztdourden08/brock-electron/node` exports the data paths (`initPaths`, `getUserDataPath`, `getLegacyPath`, `ensureDataDirectories`, `resolveDataPath`), the JSON helpers (`readJsonFile`, `writeJsonFile`) and `createNodeFileStore` with no Electron import, so a test of main-side code runs under plain Node without mocking Electron.
- `meta.keepMounted` on a hub page keeps it mounted, hidden, while another page of the same hub is open, so a running view keeps its state when the user looks at another page and comes back. On a card screen the same meta sets the screen's `keepMounted`.
- `MenuItem.useDisabled`: a hook that disables a menu entry while it returns `true`, for a module or app entry that depends on live state. The shell calls these hooks each render, so the title bar menu and the palette show the current state.
- The renderer writes its log to `Data/debug/session.log` and catches what nothing else did. `BrockApp` sends the app log there in batches through `debug:appendSessionLog` (the channel existed with no writer), and turns uncaught errors and unhandled promise rejections into error entries of the app log, in the main window and in each widget window. `sessionLog={false}` stops the writing; `catchGlobalErrors` and `writeSessionLog` are exported for an app with its own log bus.
- Settings: a normalise hook, a patch transform, a row predicate, disabled options and two control kinds. `settings.normalise(settings, stored)` mends what a profile loads before anything reads it; `settings.transformPatch(patch, settings)` rewrites every patch before it is applied, saved and seen by the effects. An item's `visible(settings)` leaves its row out of the page and the searches while it returns `false`. A choice option takes `disabled: true` or a reason, drawn on Tessera's own segmented control, select or toggle group with the option off. `control: { kind: 'color' }` and `{ kind: 'multi', options }` draw Tessera's colour and multi-choice rows.
- Buckets, pages and cards shown per host or per profile. `hosts` and `when({ profile, host, formFactor })` on a bucket of `screens.config.ts` or in a screen file's `meta` hide it where they do not hold: no menu, nav, bucket switch, rail or search entry, no shortcut, and no screen on `open`. `when` runs again on a profile switch. A menu entry takes the same rule as `show`.
- `widgetDisabled` on `BrockApp` and `WidgetHost`: a hook that returns `(id) => ({ message, settingId }) | null`, so a widget the app cannot serve right now (a session that is not running, a device that is not plugged in) shows Tessera's disabled overlay with the reason and a button to its setting, instead of being hidden. `settingId` is a route with an optional row after `#`, opened like a search hit.

## Fixes

- @drizztdourden08/brock-build@0.40.0
- @drizztdourden08/create-brock@0.40.0
- @drizztdourden08/brock-thread@0.40.0
- An app submenu named like a Brock menu section joins that section. A card or page placed with `meta.menu: 'Advanced'` made a second Advanced beside Brock's own, and the review's menu walk, which picks the first item with a label, went into the app's one, failed to find a module entry such as Controllers and left the menu open, so Escape closed the menu and the screen check failed (`<screen>-escape`). The app's entries now join the section, and the review closes the menu when a menu path it walks is not there.
- An app may declare its own `window.api` type. brock-react read and wrote `window.api` through `Window & { api?: ... }`, so an app's `declare global { interface Window { api: AppApi } }` turned those casts into type errors inside brock-react's source, which the app's own typecheck reads. brock-react now reaches `window.api` through a holder type of its own and never through the global `Window`, and the log and widget layout globals do the same. An app types its extra `window.api` members by augmenting `IpcNamespaces` in `@drizztdourden08/brock-core/augment`, or by passing its maps to `hostApi<M>()`; a global declaration of its own keeps working too.

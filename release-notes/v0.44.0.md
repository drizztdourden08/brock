# Brock v0.44.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- `@drizztdourden08/brock-build/testing` exports `waitForAppPage(app, timeoutMs?)` and `pageKindOf(url)`, so a test that launches the app itself waits for the app window instead of taking the splash from `firstWindow()`. `launchAppForTest` takes `userData`, the app's own profile folder with the test's fixtures, which `close()` leaves in place.
- The boot watchdog is configurable: `product.boot.devWatchdogMs` (default 120000) and `product.boot.watchdogMs` (default 8000) in `brock.config.ts`, and the `BROCK_BOOT_WATCHDOG_MS` environment variable, which overrides whichever applies.
- Tessera 0.35: DensityScope and the parts that replace the last app-side styles of a part.

## Fixes

- A dev launch no longer gets stuck on the splash. The splash plugin loaded brock-core through `vite.runnerImport` on every `index.html` and `splash.html` request, which took over 20 s inside a busy dev server; it now works the look out once per dev server, starting when the server starts, and again only when `brock.config.ts` or a file it reads changes. When the renderer answers after the boot watchdog fired (a heartbeat, progress, or a late `boot:ready`), main clears the watchdog's failure, the splash goes back to the progress and the app is revealed as usual; the app window's `did-finish-load` now counts as a sign of life too. The development watchdog waits 120 s instead of 30 s.

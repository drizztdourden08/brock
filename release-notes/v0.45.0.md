# Brock v0.45.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- The Capacitor host reports the edge of the back gesture: `device.onBackButton` gets `left` or `right` from the `brock:back` event the Android `MainActivity` dispatches, and the app exits when nothing listens. The Android scaffold writes that activity in place of Capacitor's empty one (with `android:enableOnBackInvokedCallback` in the manifest), and leaves an activity with code of its own alone; run `platform add android` again to add it to an existing app.
- Packaging takes more from the product. The Windows exe gets its version info stamped beside the icon: company from `product.author`, product name and file description from `product.name`, `LegalCopyright` from the new `product.copyright` (else the year and the author), comments from `product.description`, and the app version. `product.linuxCategory` (a main freedesktop category such as `Game`) sets the deb's and the AppImage desktop entry's category, and the AppImage entry gets the description as its comment. A file association takes a `description`: the Linux mime comment, the Windows ProgId tooltip and electron-builder's association description.
- Workflow steps can target one job: a step's `jobs` (one id or a list) keeps it to those jobs of its point, `quality`, `review`, `web`, `changes` or `workspace` in CI and `prepare` or `build-<platform>` in the release. The new `release.prepare` point runs in the `prepare` job after the install, before its release note check and lint.
- `filePicker.pickFile({ extensions, anyType: true })` opens the picker with no type filter, for a file whose extension the system has no type for (Android's picker greys such a file out); the app then checks the name it gets. Without `anyType` every host filters by `extensions` as before.
- `product.window.titleBar.mobile: false` leaves the title bar out on a mobile form factor, for an app that draws its own phone chrome; it stays on the desktop, and the default keeps it everywhere.
- The `--screenshot` watchdog is configurable and fails loudly: `--screenshot-timeout=<seconds>` or `bootstrapApp({ screenshotTimeoutMs })` sets how long it waits (20 s by default), and when it fires it still captures, logs whether the window never revealed or how many screenshot holds were open, and exits 2 instead of 0.
- The Storage page works on a phone: `<BrockApp dataDomains>` gives the renderer the app's data domains, the Capacitor storage port sums each one through the Filesystem plugin, and the page shows the data folder and each domain's size and item count with no action the phone cannot run. `setDataDomains` and `rendererDataDomains` are exported.
- `createGameCore(port, { watchCrashFrom: 'start' })` arms the crash watch when the core starts, before the glue script loads, so a WebAssembly runtime error while the core boots sets the `error` state and reaches `onCrash` instead of going unseen; the default `'running'` keeps today's behaviour. `watchCoreCrash` is exported for an app that loads its core itself.
- ensure-wasm finds the Emscripten SDK from a git worktree: when the worktree has none at a relative `emsdkDir`, the same folder of the main checkout is used, read from the worktree's `.git` file with no git call. `emsdkOf` reports `mainCheckout`, and `mainCheckoutOf(dir)` is exported. `$EMSDK` and an absolute `emsdkDir` still win.
- Save slots can write raw states: `createSaveSlots({ format: 'raw' })` and `createPortSession({ saveFormat: 'raw' })` write the core's state bytes as they are (after the save transform) instead of the PKSV container. Loading already took both.
- `RomStore.listNames()` (and the same call on each kind's store) lists the stored ROM files by name only, with no read and no hash: `{ file, label, hasAssets }`, for a listing that has to show at once.
- The update notice gets the release: the function given to `setUpdateNotice` now receives `releaseNotes` and `release` (`{ tag, name, url, publishedAt, prerelease, assets }`, each asset `{ name, url, size, contentType }`, or `null` when unknown), so an app can warn per version from what the release carries, such as a file that marks a change to saved data. `UpdateInfo` and `VersionOption` carry the same `release`.

## Fixes

- A main process worker imported with `?modulePath` now builds. The managed main config named `electron/main.ts` as a library entry, which made electron-vite's worker bundle return one output per library format and stopped the build; it is now a build input, so `import workerPath from './job.worker?modulePath'` gives a file beside `main.js` that `new Worker(workerPath)` and port-kit's `runAssetWorkerJob` start. A test builds such a worker through the managed config and runs it.
- A plugin that `brock.workspace.mjs` lists as an object (the imported `definePlugin` result) now loads once: discovery skips a declared `brock-plugin-*` package or a dot-folder plugin whose name matches a plugin already loaded, so its verbs and workflow steps are no longer counted twice.

# Brock v0.46.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- The renderer dev server pre-bundles what Brock can find before the first page loads, so a cold start runs Vite's dep optimizer once instead of finding dependencies as the page asks for them, re-running it and reloading. `defineBrockViteConfig` sets `optimizeDeps.include` on the dev server: React and `react-dom/client`, the renderer entries of Tessera and of the Brock packages installed in `node_modules`, and every package import of the files under `src/` and of the linked workspace packages they reach (deep icon imports and the imports of worker files included; an import only a linked package can resolve is written `<linked> > <dep>`). The new `build.optimizeDeps` in `brock.config.ts` takes `include`, `exclude`, `entries` and `worker`, the dependencies only a renderer Web Worker imports that the source read cannot see (`worker: ['fs', 'crypto', 'path']` with `nodePolyfills`).
- Title bar items in the order an app chooses. A `src/title-bar/<id>.action.ts` file may export `order` (`export const order = 2`) or `meta: TitleBarItemMeta` with `order`, as screens do; `brock sync` carries it into `.brock/title-bar.ts`, and `titleBarFromFiles` puts the items with an order first, in that order, then the rest by id. Files without one keep the id order, so renaming files to order them is no longer needed.
- `pickFile({ anyType })` takes a host or form factor (`'mobile'`, `'desktop'`, `'electron'`, `'capacitor'`, `'web'`) or a map of them such as `{ mobile: true }`, and drops the type filter only there, so a phone opens the picker unfiltered while the Electron picker keeps its filter. A host key wins over the form factor key. `true` still drops it on every host. `anyTypeFor(anyType, info)` from brock-core resolves the value.
- The app names its profiles route, and a bucket can open without a profile. `product.profilesRoute` (for example `'data/profiles'`, a hub page) makes every way to the profiles screen land there: the Profiles menu entry, the `profiles` boot task (no profile, an unknown pinned profile, several profiles and no last one), deleting the active profile through `useProfiles` and `open('profiles')`. Brock's own `profiles` screen is then not registered, and `ProfilesScreen` closes the hub after a pick on that route. Unset, nothing changes. `requiresProfile: false` on a bucket in `screens.config.ts` (or a `defineHub` def) lets its hub open while no profile is active, so a first run can reach that page to create a profile.
- Asset jobs run in a renderer Web Worker too, with no main process. `runAssetWebWorkerJob(options)` from `@drizztdourden08/brock-port-kit/renderer` takes the options of `runAssetWorkerJob` with the worker constructor of a `?worker` import, and the Web Worker serves the steps with `serveAssetSteps` from the new `@drizztdourden08/brock-port-kit/web-worker` entry. One `AssetWorkerSteps` object serves both sides: each step now gets the job's `workerData` as a third argument (the thread's `workerData` in Node, posted once to a Web Worker). The job is a renderer job: `jobs.start(id, steps, options?)` from brock-react returns the same `JobHandle` as `ctx.job`, its snapshots go into the job store, so the job dialog and the title bar show it on every host, and `jobs.cancel` and `jobs.dismiss` reach it. The job registry moved to brock-core (`createJobRegistry` and the `JobHandle`, `StartJob`, `JobRegistry` types from `@drizztdourden08/brock-core/jobs`); brock-electron re-exports the types as before.
- App state in show rules. `<BrockApp showFlags={{ signedIn }}>` passes the app's own flags to every `hosts` and `when` rule as `ctx.flags`, so a page, a bucket, a card or a menu entry can show only while, say, the user is signed in: `when: ({ flags }) => flags.signedIn === true`. `useShowFlags({ ... })` adds flags from any component while it is mounted, which is how a module contributes them from its `Provider`; the app's prop is applied last. When a flag changes, the menu, the hub nav, the search palette, the bucket switch, the rail, the shortcuts and the open screen evaluate again. `ShowFlags` in `@drizztdourden08/brock-core/augment` types the flags. `ShowContext` now has `flags`, so code that builds a `ShowContext` by hand for `isShown` adds `flags: {}`.
- Tessera 0.36, and small informational windows. A card whose meta sets `size: 'info'` opens like About: a small window sized to its content and centred, at most `--size-512` wide and at most the window's height, with no page header (the window title bar names it) and its content scrolling inside; under 560 px wide it fills the window. Brock passes it to Tessera's `ScreenWindow` as `size="info"` (`ScreenDef.size`, `ScreenSize`). The built-in Credits screen and the template's `credits.card.tsx` open this way. About opens small on its own: Tessera's `InfoScreen` now always opens at `size="info"`, and its `width` prop is gone (Brock never used it).
- A hub header backdrop. `backdrop` on a bucket in `screens.config.ts` (or on a `defineHub` def) draws behind the header of every page of the hub, and `backdrop` in a page's `meta` overrides it for that page and its sub-pages. It takes the shape of a hero backdrop: `{ kind: 'node', node }`, `{ kind: 'image', src, fit?, position?, tileSize?, color?, pixelated? }`, `{ kind: 'color', color }` (a CSS colour or a token name such as `'--c-secondary'`), or `{ kind: 'none' }` to draw no art. `HubPageFrame` passes it to Tessera's `ScreenPage` and `SettingsPage` and through the settings page context, so settings pages get it too; without one the header keeps Tessera's art.
- One menu per hub, and only when it helps. A bucket in `screens.config.ts` (or a `defineHub` def) takes `nav: 'auto' | 'always' | false`, `'auto'` by default: the hub draws its side nav only while two pages or more are shown, and with one page shown it draws that page alone, with no side nav and no hub search field. The nav comes back as soon as a `when` rule, a host rule or developer tools show a second page. `'always'` keeps the old look for one page, and `false` never draws the nav. Back, the history and Escape (up to the hub home, then closed) work the same without the nav. The review's hub checks pass a hub with no nav: `<hub>-pages` checks that no nav is drawn, each page opens with `open` instead of its nav entry, and the hub search runs in the first hub that has one.
- Credits, About and Quit close the menu. They were split, with only Quit in the menu's last group, so the View sub-menu and the title bar actions landed between About and Quit. Credits, About and Quit now form the last group, in that order, in every app. The review's menu step checks it (`menu-ends`).
- The browser host detects a phone. It reported `formFactor: 'desktop'` everywhere; it now reports `formFactor: 'mobile'` where a coarse pointer meets a narrow viewport (at most 767 px wide, or 500 px high for a phone held sideways) and `input: 'touch'` for a coarse pointer, and `PlatformProvider` follows both media queries, so the info changes with the viewport. `when` rules on `formFactor`, mobile-only settings tabs, the `platform-mobile` class and the search index now work in a phone's browser as they do in the Capacitor app, and the browser file picker reads the form factor when it opens, so `anyType: 'mobile'` drops its filter in a phone's browser too.
- `listNames()` entries carry `assetBytes`, the size of the ROM's asset blob read from the file store's `stat` (`null` when there is none or the stat fails), still with no read and no hash, so a Data Manager can show "Extracted (12 MB)". `hasAssets` now comes from the same stat.

## Fixes

- A dev boot no longer clears Chromium's HTTP cache every time, which threw away the pre-bundled dependency chunks. Main keeps the cache while the renderer's dep optimizer hash (in the `_metadata.json` the dev server names in `BROCK_DEV_DEPS_METADATA`) is the one of the last dev boot, and clears it once when the hash changes. `BROCK_DEV_CLEAR_CACHE=1` clears it on every dev boot, as before. Edits still show at once: Vite serves source modules and `public/` files with `no-cache`.
- Asset jobs run in a renderer Web Worker too, with no main process. `runAssetWebWorkerJob(options)` from `@drizztdourden08/brock-port-kit/renderer` takes the options of `runAssetWorkerJob` with the worker constructor of a `?worker` import, and the Web Worker serves the steps with `serveAssetSteps` from the new `@drizztdourden08/brock-port-kit/web-worker` entry. One `AssetWorkerSteps` object serves both sides: each step now gets the job's `workerData` as a third argument (the thread's `workerData` in Node, posted once to a Web Worker). The job is a renderer job: `jobs.start(id, steps, options?)` from brock-react returns the same `JobHandle` as `ctx.job`, its snapshots go into the job store, so the job dialog and the title bar show it on every host, and `jobs.cancel` and `jobs.dismiss` reach it. The job registry moved to brock-core (`createJobRegistry` and the `JobHandle`, `StartJob`, `JobRegistry` types from `@drizztdourden08/brock-core/jobs`); brock-electron re-exports the types as before.
- A file dropped outside a drop target no longer replaces the app with that file. The app window and every widget window cancel a navigation that leaves the page: a reload, the same origin (the dev server) and a hash or query change of the same page stay, a link with a protocol of `security.externalProtocols` opens in the system browser through `openExternal`, and anything else is dropped. `setWindowOpenHandler` still denies every new window and hands its link to `openExternal`.
- A check now finds a newer pre-release published before a newer stable hotfix. The check answers from the version list (the first listed version newer than the installed one, following Include pre-releases) instead of Velopack's check, which looks at a single GitHub release, so the check, the "Update available" badge and the install target agree. The version list reads every listed release's own `releases.<channel>.json` and keeps only that release's entries, since each feed holds only the packages that existed when it was packed; a failed feed read drops only its own release, and the list fails only when every read fails.

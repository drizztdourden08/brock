# Brock v0.47.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- A product wordmark. `product.icons.wordmark` names the app's name drawn as an image, an SVG or PNG under `public/` given as a path like the logos (`'./logos/wordmark.svg'`), or `{ src, dark }` with a variant for the dark splash ground. `defineProduct` resolves it to `{ src, dark }` (`dark` defaults to `src`, new types `ProductWordmark`, `ProductWordmarkInput` and `ProductIconsInput`) and refuses a file that is not `.svg` or `.png`. When it is set, the boot splash and its failure screen, the window's failure splash (`BootFailureSplash`) and the Setup splash `brock package` renders show the `dark` image in place of the name text, and the About window shows `src` as its heading (`AboutPanel` takes `wordmark`). The image keeps the name as its accessible name. Unset, nothing changes. The splash page uses `ts-wordmark` ahead of Tessera shipping it and sizes the image itself until then; the window's failure splash paints the image over the name text until Tessera's `Splash` takes a wordmark image.
- `<BrockApp profiles={{ onBeforeRemove }}>` runs before a profile is removed, after the delete confirm. It gets the profile, may be async, and keeps the profile when it returns `false` or throws (the error is logged), so an app can stop the work tied to that profile, such as a running session, or refuse while it runs. `profileRemoval.add(fn)` registers one from outside React and returns the remove call. `useProfiles().removeConfirmed(profile)` now resolves `true` when the profile was removed and `false` when a hook kept it.

## Fixes

- Standards 0.11: a `@kind verbatim` file also skips the vendor and assistant name check for its string values.
- A title bar action file may export `order` or `meta` beside its default export, as screen and widget files may. A ROM whose asset file is empty lists as having no assets (`hasAssets: false`, `assetBytes: 0`).
- Deleting the active profile no longer leaves a blank window where Escape and Home do nothing. When other profiles remain, the most recently used one becomes active and the user stays on the screen they are on; only when the last profile goes does the app open the profiles route (`product.profilesRoute` when set, else the `profiles` screen). Deleting a profile that is not active changes neither the active profile nor the screen. With no active profile and a home screen that needs one, Escape with nothing open opens the profiles route, Escape on that route keeps it open instead of closing it to an empty window, and the Home menu entry shows as disabled with the reason, Pick or create a profile first.

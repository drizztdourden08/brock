# Brock v0.49.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- A bucket's header backdrop can be a component: `src/screens/<bucket>/<bucket>.backdrop.tsx` default-exports it, and `brock sync` lists it in `.brock/screens.ts` as a `backdrop` entry loaded with `lazyComponent`. `buildScreenTree` makes it the bucket's `{ kind: 'node' }` backdrop inside a `Suspense` with no fallback, and its load joins the preload of the hub home and of every page, tab and sub-page of the bucket, so a bucket switch pill, a menu row or a hub nav entry on hover or focus and the boot preload load it before the header draws. It wins over `backdrop` in `screens.config.ts`, and a page's `meta.backdrop` still wins over both. `brock structure` reports a backdrop file not named after its bucket or outside its bucket folder, a bucket folder holding only a backdrop, and a bucket that has both the file and the config field; the file takes a `<bucket>.backdrop.constants.ts`. The lint config treats it as a screen file (a default export). brock-react exports the `BackdropEntry` type.
- The app can now change the title bar menu Brock builds, entry by entry, while the detected menu stays the default. `product.menu.entries` in `brock.config.ts` and the same object in a screen's `meta.menu` take, per entry key, `inMenu: false` (out of the menu only, still reached by the search palette, its route and its shortcut), `hidden: true` (out of the menu, the search palette and the keyboard shortcuts, still openable from code by its route), `label`, `group` (`'main'`, `'sections'`, `'modules'` or `'end'`), `order` (like CSS `order`, 0 by default), `before` and `after` another entry's key, and `parent` (a submenu's key, or `null` for the top level). They merge in that order, the app config last. Every built-in entry, section, bucket, page, card and module entry has a stable key; docs/app-structure.md lists them. The View sub-menu takes only a label, since the title bar draws it. `brock check` reports a field it does not know, a wrong value, a `bucket:` or `screen:` key no screen file gives, an entry that names itself and a `before` and `after` loop; a development launch logs the rest once each, such as a key no entry has or a parent that is not a submenu. Nothing throws: an override that cannot apply is skipped. With no active profile, every menu entry that opens a screen needing a profile now shows as disabled with the reason, Pick or create a profile first, as Home already did, instead of looking enabled and opening nothing. The review's menu checks follow the effective menu: the built-in entries and the last group are read where the overrides put them, a hidden screen is no longer expected in the menu, each overridden entry gets a `menu-entry-<key>` check that it is out of the menu, or drawn at its place between its neighbours, and each hidden entry a `search-hidden-<key>` check that the palette does not list it.
- New job options for `ctx.job` and `jobs.start`: - `visible: false` runs a quiet job. It reports progress like any other job and its snapshot carries `visible: false`, but it stays out of the title bar item and the job dialog. It clears itself 30 s after it ends, whether it succeeded, failed or was cancelled. Every `JobSnapshot` now has `visible`. - `forwardLog: true` also writes the job's log lines to the app log as `[job <id>] <message>`. A main job writes through `ctx.log`, a renderer job to the `app` channel. The app log keeps the lines after the job is gone. - `onDuplicate` sets what starting an id that is still running does. `'throw'` is the default and keeps today's "already running" error. `'queue'` starts the new job under the same id once the running one ends. `'parallel'` starts it under the first free `<id>-2`, `<id>-3` and so on. `'join'` returns a handle on the running job, whose `run` resolves with that job's result instead of running the work again. `JobHandle` gains `started` (resolves once the job runs) and `ended` (resolves with `done`, `failed` or `cancelled`), so a hand-written `JobHandle` fake needs both. `createJobRegistry(emit, now?, sink?)` takes a sink for the forwarded log lines. `useJob(id)` also returns `step`, the current step with its label, beside `job`, which is `null` when no such job is known. It follows main and renderer jobs alike, so a page can show a job's progress inline.
- Hub page headers draw their backdrop through Tessera's `BackdropLayer` (Tessera's `backdropStyle` paints an image or a colour), and Brock's own `HubBackdrop` part, its `backdrop-style.ts` and the `.hub-backdrop` classes are gone; style `.backdrop-layer` if a hub needs more. A node backdrop now fills the layer the way it fills a Hero. A `.hero.tsx` sets `meta.hero.size` (`'compact'`, `'default'` or `'tall'`, new `HeroMeta` type) and the hero frame passes it to Tessera's `Hero` as `size`.

## Fixes

- Tessera 0.37.1 draws the splash wordmark. `BootFailureSplash` passes `product.icons.wordmark.dark` to Tessera's `Splash` as `wordmark`, so the heading is a real image named by the app name, and its own `BootFailureSplash.css` and wordmark helpers are gone. The static splash page writes `<img class="ts-wordmark">` and drops Brock's `.splash__wordmark` rules for Tessera's. Both splashes look as before. brock-react's Tessera peer range is `^0.37.1`.
- Screens now preload from Tessera 0.37.1's `onHighlight` instead of matching the hovered row's label text. Every title bar menu item that opens a screen, every hub nav entry, every hub switch pill and every search palette row with a target preloads the route it opens when it is pointed at, focused, reached with the arrow keys or, in the palette, becomes the active row. Two rows with the same label, a renamed menu entry and a moved one each load their own screen. `usePreloadOnHover` and its label lookup are gone.

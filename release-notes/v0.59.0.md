# Brock v0.59.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- Breaking: a `volume` title bar item no longer takes `labels`, and brock-react no longer exports `TitleBarVolumeStrings`. Tessera's volume bar item draws the Mute and Unmute labels from its own strings, so an app that passed `labels` removes it. The `volume-item-labels` migration (0.59.0) leaves a to-do where `labels` sits in a file with a volume item, and on each use of `TitleBarVolumeStrings`.
- A Developer submenu in Widgets, and menu placement for widgets and kits. Every `devOnly` widget and every `devOnly` kit now sits in Widgets > Developer (key `widgets-developer`), so a developer kit reads Widgets > Developer > its label > Open kit, its widgets, its overlays and Reset kit layout. Developer shows only while developer tools are on, and it is left out when nothing goes in it. `WidgetMeta` and `WidgetKitMeta` take `menu: { parent, group, order }` (the `WidgetMenuPlacement` type), placed like the same fields of `product.menu.entries`. When a widget, a kit or Developer names a `parent` that no entry has, in its meta or in `product.menu.entries`, that submenu is made inside Widgets, labelled from its key (`audio-tools` reads Audio tools), and the menu config renames or moves it by that key; `parent: 'widgets-developer'` files any widget or kit under Developer, and `parent: null` in the config keeps a `devOnly` one out. `brock structure` accepts `menu` in widget and kit files and reports a placement with an unknown field or a wrong value. The review registers a `devOnly` widget and kit and checks that Developer lists them with the kit as its own submenu, and, in a packaged review, that Developer is gone while developer tools are off; each `devOnly` app kit gets an `app-kit-<id>-in-developer` check.
- `product.icons.wordmark` takes `rendering`: `'auto'` (the default, smooth scaling) or `'pixelated'`, for pixel art that should scale with hard pixel edges. With `{ src: './logos/wordmark.png', rendering: 'pixelated' }`, About, the boot splash page, the window's failure splash and the Setup splash draw the wordmark with `image-rendering: pixelated` (nearest neighbour on the Setup splash); without it nothing changes, since most logos look wrong pixelated. `defineProduct` keeps `rendering: 'pixelated'` on the resolved wordmark and refuses any other value. `AboutPanel` takes `wordmarkRendering`.
- `widgets.force(ids)` forces widgets open, for command line baselines and end-to-end runs on a fresh profile. Each id opens (a kit widget opens its kit), at once or as soon as its definition is registered, and again after each profile loads. A forced widget skips the context gate and the developer tools gate, docked, floating and popped, and a forced kit widget lets its kit past the kit's `devOnly` and `requires` gates. The list replaces the previous one, and `widgets.force([])` ends forcing. An app reads its own flag, such as a `--widgets=` argument, and passes the ids. The review checks a forced kit widget past its gate (`kit-forced-opens`, `kit-forced-released`).
- Brock moves to Tessera ^0.41.0, and a `volume` title bar item is now Tessera's volume bar item: a 28 px volume control whose slider opens on hover or focus, and a click on it mutes. Once it folds, the main menu holds a Mute or Unmute row and a slider row. The spec is unchanged (`kind: 'volume'`, `label`, `value` from 0 to 1, `muted`, `onChange`, `onMuteToggle`, `shortcut`), and Brock calls `onMuteToggle` when Tessera asks for the other muted state. The review's `volume` step now also checks that hover or focus opens the slider and that moving it changes the volume, and the narrow menu must hold both rows. Apps upgrade with `brock migrate`.
- Settings pushed before the core runs are no longer lost. `createLiveSettings(core)` listens to the core and applies the last pushed settings each time the core starts running, and again after a restart; a plain `{ calls, apply }` target can pass `subscribe` for the same. The new `dispose()` stops listening. `createPortSession` applies the settings pushed while the core loaded when it starts, and uses its `settings` option only when nothing was pushed, where it used to overwrite them with the option.

## Fixes

- Screenshots no longer catch a loading spinner. Each lazy load (a lazy screen, widget, title bar item or tour) now holds the screenshot from its start until it settles and a frame has painted, so `--screenshot` waits for it like any other hold. The review's own captures (`review:capture`, `review:captureWidget`, `review:captureGroup`) now wait for the same holds too, up to 10 s; a hold still open then fails a `capture-holds` check for that step and the capture goes ahead.
- A wide `product.icons.wordmark` now fits the About card. Before, the image frame had a fixed `--size-48` height, so it was as wide as the picture at that height, and the centred heading grew to that width: a wordmark wider than the card was cut on both sides, and at a narrow window the whole panel spilled out of the card. The panel now takes the width it is given, up to `--size-448`, and the image fills it with its height following its proportions up to `--size-48`, centred, so any wordmark fits however wide it is. The review checks it: `about-wordmark-fits` fails when the wordmark's left or right edge passes the card's. The splashes already fitted it and are unchanged.
- A page now hides an open widget kit. Opening Home or any screen while a kit is open used to draw the page inside the kit's main cell, with the kit's widgets, overlays and bar still around it. Now the kit steps aside like a context-only widget: its docked and floating widgets, its overlays and its bar are hidden, the kit stays open with its layout untouched, and it comes back as it was when the page closes. Its popped windows follow the normal popped rule on a page. The review checks it (`kit-page-hides`, `kit-page-returns`).

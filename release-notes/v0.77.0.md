# Brock v0.77.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- Live hub pages. A `<id>.live.tsx` file in a bucket or group folder is a slot in the hub nav that fills at runtime. It default-exports a hook that returns `LivePage[]` (`key`, `title`, `icon`, `badge` of `'ok'` or `'warn'`, `render`) and exports `meta: LiveMeta` (`icon`, `empty`, `title`, `order`, `keywords`, `devOnly`). The slot sorts by `meta.order` among the static pages, so Directory, one entry per connected pad, then Logs and Diagnostics keep their order. The badge shows as a status dot on Tessera's `SideNavItem`, `empty` shows as a disabled nav entry while the list is empty, and `keywords` feed the hub search. An entry opens at `<bucket>/<id>/<key>` (`section` and `tab`); when it disappears, the hub shows the first static page of the group. `brock sync` reads the file as an eager kind, and `brock-lint-config` treats it as a screen file. See Live hub pages in `docs/app-structure.md`.
- Recent documents and recovery snapshots for document apps. The documents port gains `recent()`, `clearRecent()` and `openRecent(path)`, a capped per-profile list that main fills on Open and on save, drops missing files from, feeds to the OS jump list and Dock menu, and reopens only through the document allowlist. It also gains opt-in `snapshot(key, data)`, `recoverable()`, `restoreSnapshot(key)` and `discardSnapshot(key)`, stored atomically in the profile folder and cleared on a clean save. brock-react adds `useRecentDocuments`, `useRecentMenu`, `useRecoverable` and an optional `RecoveryPrompt`.
- An opt-in menu bar row. Pass `<BrockApp menuBar>` a list of `{ id, label, entries }` menus whose entries are command ids, `'separator'` or `{ label, entries }` submenus, and the app draws a row of menu buttons under the title bar. Labels, icons and chords come from the command registry, so a remap shows at once, and an entry is greyed out while the command's `when()` is false. Alt opens the first menu, the arrow keys move between menus and items, and Escape closes. The hamburger stays.
- A title bar button spec takes `disabled`. A button with a `command` is disabled while the `when` of that command returns false, and the bar re-reads it each time the component that registers the command renders, so Undo and Redo follow the document. A disabled button ignores clicks. Brock hands Tessera `disabled: true` on the bar action; Tessera 0.52 has no disabled look for title bar actions yet, so the button is not dimmed until it does.
- `window.api.input.mapping.list()` returns every gamepad mapping SDL knows as `{ guid, name, vid, pid, platform?, family? }`, so an app can show a searchable directory of supported controllers. The vendor and product ids are decoded from the SDL GUID, the platform comes from the mapping line, and the family comes from the vendor or the name. Main parses the list once and clears it when a mapping is added. The addon adds a `mappingList` call and moves to version 1.3.0. With an older addon, with controllers off, or on Android, `list()` returns an empty list. See the mapping directory section of the module README.

## Fixes

- The knip config that `brock adopt` writes, and the app template, now list `src/views/*/*.usage.ts` as entries. Tessera usage files are read by tooling and never imported, so knip no longer reports them as unused. A lazy title bar button also keeps a literal `disabled` from its spec.

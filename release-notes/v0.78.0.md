# Brock v0.78.0

An app can now ship a helper program, such as an MCP server, that talks to the running app over a private local bridge.

## Changes

- Add helper entries. `helpers` in `brock.config.ts` names standalone Node entries. `brock build` and `brock dev` bundle each one into `dist/helpers/<name>.mjs` with only Node built-ins as imports, and refuse an Electron import. The installer ships them in `resources/helpers` outside the asar. `helperLaunch(name)` gives the command, arguments and environment for an MCP client config.
- Add the local bridge, off until an app opens it with `bootstrapApp({ bridge: { register } })`. Main listens on a per-session named pipe on Windows, or a private Unix socket elsewhere, and never on TCP. A random per-session secret guards it, and the secret never crosses the wire: both ends prove they hold it before any request, and each request carries its own proof. The discovery file lives in the per-user app data folder, is private to the user, and is cleared when stale and removed on quit. Routes are `invoke` entries, take a `validate` check, and hide handler errors unless they are a `BridgeError`. The helper connects with `connectBridge` from the new `@drizztdourden08/brock-electron/bridge` entry, which imports nothing from Electron. Read "Outside helpers and the bridge" in `docs/architecture.md` before you add routes: a route must stay narrow and validate its arguments.

# Brock v0.80.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- Breaking: `ctx.window` is now a function with a `show()` method and `AutomationFlags` gains `isBackgroundLaunch()`, so a hand-built `MainContext` or flags object in a test needs the new members; migration main-context-window-show leaves a to-do at each one. feat: background launch and an opt-in tray icon An app can start with no window. A `--background` launch, or a `beforeWindow(ctx)` hook that returns `'skip'`, skips the splash and the app window while the whole boot and the bridge still run. `ctx.window.show()` creates the window on demand, or restores and focuses it. In background mode the app keeps running when the last window closes. A normal second launch shows the window, a second launch with `--background` shows nothing, and automation launches behave as before. `product.tray` or `ctx.tray.set({ tooltip, icon?, menu? })` adds a tray icon. It uses the app icon by default, a left click shows the window, the menu takes show and quit actions, id items for `ctx.tray.onItem` and separators, and the tray is removed on quit. It is off unless the app asks.
- Breaking: hub pages draw no big page header by default, and the app can take over the content side of a hub. A page shows the header only with `showHeader: true` in its meta (a page that declares `header: { primary, search }` keeps it, a page with tabs keeps its tab bar, a sub page keeps its back button); a page that fills the header with `PageActions` needs `showHeader: true`. Migration `hub-page-header-off` (0.80.0) lists each hub page and custom page without a header setting as a to-do. New: `bare: true` in the meta of a `.page.tsx`, `.custom.tsx`, `<page>.page.ts` or `.live.tsx`, or on a `LivePage` entry, renders the page straight into the content slot with no card, padding, header or scroll area, named by the page title for assistive tech. `pages: 'bare'` on a bucket (or `HubDef`) makes every page of the hub bare, and a page opts back in with `bare: false`. `WindowItem` takes `bare: true` to drop the pane scroll area of one `defineWindow` item. `HubPagesMode` is exported.
- Breaking: the helper bridge moves to protocol 2, so a helper built against 0.78 or 0.79 cannot talk to an app on this version and must be rebuilt (`brock build` bundles it again) and shipped with the app; `bridge.emitTo` now returns a count. Migration `bridge-protocol-2` turns each `connectBridge` use and each `.emitTo(` into a to-do, since the fix is a rebuild and a release, not a code edit. Bridge v2. `ctx.bridge.open()` and `ctx.bridge.close()` open and close the bridge at run time, each open with a new secret and endpoint, and serialized so a close and a reopen never remove the live discovery file; `bridge.openOnBoot: false` keeps it closed until the app opens it. `bridge.handleWith(route, (call, ...args) => ...)` gives handlers `call.connectionId` (16 random bytes, not a capability), and `bridge.onOpen`, `bridge.onClose` and `bridge.connections()` follow clients; a throwing listener is logged. `bridge.emit(event, ...args)` and `bridge.emitTo(connectionId, event, ...args)` push events, which the helper hears with `client.on(event, listener)` after `client.connect()`. The client authenticates with the session key before any request, and every server message is signed with it, pushes with their own counter. Each connection holds at most `maxBufferedBytes` (4 MiB) of unread output: pushes past it are dropped and a reply that does not fit closes the connection. `BridgeError` takes `{ code, data }`, which reach the client as fields; other errors stay masked, and Brock's codes are in `BRIDGE_CODES`. The client reads the discovery file through one handle with no link followed, checks that handle and, on macOS and Linux, the folder. `helperLaunch(name)` sets `BROCK_BRIDGE_FILE` to this app's discovery file.
- Packaged apps now flip Electron fuses in the managed electron-builder config. `EnableNodeOptionsEnvironmentVariable` and `EnableNodeCliInspectArguments` are off, so `NODE_OPTIONS` and `--inspect` no longer work on a packaged app. `OnlyLoadAppFromAsar` and `EnableCookieEncryption` are on, and `EnableEmbeddedAsarIntegrityValidation` is on for Windows and macOS builds (Electron has no asar integrity on Linux, so it stays off there). `RunAsNode` follows `helpers`: on when `brock.config.ts` declares helpers, since they start through `ELECTRON_RUN_AS_NODE`, and off otherwise. The new `fuses: { runAsNode }` option overrides it; `false` beside declared helpers is refused. `brock dev` and the headless launches use the dev Electron and are unchanged. The cookie fuse is a one-way change for existing cookie stores. The managed `files` list also leaves out hidden folders inside `node_modules`: a linked package is packed whole, and files that change while the asar is written make its integrity data wrong, which the integrity fuse turns into a start-up failure.
- Start-up prompts and a richer confirm dialog. A start-up prompt is `src/startup/<id>.prompt.ts`, default-exporting `defineStartupPrompt({ order?, run(ctx) })`; `RendererModule.startupPrompts` adds a module's. Brock runs them once per launch, one at a time in `order`, after the window reveal, once a profile is active with its settings loaded and after any first-run tour has ended or been skipped, and never on an automation launch. A prompt that throws is logged and the next one runs. `ctx` carries `confirmAction`, `confirmChoice`, `confirmSave`, `profile`, `settings` (`get`, `patch`, `flush`) and `nav`. `brock sync` writes `.brock/startup.ts` (a prompt with a literal `order` loads when it runs), `src/main.tsx` passes it as `startupPrompts` (the `startup-prompts` migration of 0.80.0 adds that), `brock structure` checks the folder and the lint preset lets prompt files default-export. `confirmChoice` takes `look: 'select'` (Tessera's `Select`, with `searchable`) in place of the radio group and still resolves the picked value, or `null` on cancel. Every confirm dialog takes `facts: { label, value }[]`, drawn under the message with Tessera's `FactsPanel`. Defaults are unchanged.

## Fixes

- The Windows addon build unpacks libusb with 7-Zip instead of tar, and skips the download when native/third_party already holds the pinned libusb version.

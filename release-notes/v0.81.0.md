# Brock v0.81.0

An app can now let the user grant a whole folder, then read, write and list files inside it.

## Upgrading

- Await `ctx.documents.resolve` and `ctx.documents.isAllowed` in main code. Both now return a promise. Migration `documents-access-async` leaves a to-do at each call that is not awaited.
- Expect the recent list to empty once. Recent entries are now signed with a key per install and checked when read, so the entries an earlier version wrote are dropped. Document calls that name a profile need an existing profile.

## New

- Grant folders. The user picks a folder with `documents.openFolder(options)`, or main code calls `ctx.documents.allowFolder(path)` and `revokeFolder(path)`. Every file inside a granted folder, at any depth, then passes for `read`, `readText`, `write` and `writeText`. The check runs on the real path on every call, so `..` segments, links that lead outside, look-alike sibling folders and Windows raw prefixes, streams and device names are refused.
- List a granted folder. `ctx.documents.list(folder, { extensions, recursive })` in main and `documents.list(folder, options)` in the renderer return `{ entries, truncated }`, bounded to 5000 entries, 8 levels and 5 seconds.
- Read the recent list from main with `ctx.documents.recent(profileId)`.

## Under the hood

- Refuse grants that reach the app's own folders, the home folder or system folders such as AppData, Library, .config, Program Files and Windows.
- Refuse writes under a grant into autostart paths, repository and editor configuration (.git, .husky, .vscode, .idea, .devcontainer, .github/workflows, and files named HEAD, commondir or gitdir) and Windows shortcut and Explorer files such as .lnk, .url and desktop.ini.
- Mark executables, macro documents, archives and disk images written under a grant with the Windows Mark of the Web, so a double click still shows the usual warnings.
- Keep files reached only through a grant off the recent list.

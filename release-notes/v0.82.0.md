# Brock v0.82.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- ControllerLayout, StickPlot and PressedGrid move from Tessera to the input module. They keep their props and types, and the module exports them from `@drizztdourden08/brock-input/renderer` with `CONTROLLER_LAYOUT_VARIANTS`, `CONTROLLER_SLOT_IDS`, `ControllerExtra`, `ControllerSlots` and the prop types of each. `CalibrationPanel` and the device card now use the local copies. The controller strings (`Controller`, `Held now`, the slot names) ship with the component, so a Tessera strings override no longer reaches them. The BEM block of each part gains an `input-` prefix (`input-controller-layout`, `input-stick-plot`, `input-pressed-grid`), so an app stylesheet that reached into the old classes needs the new names. The `controller-components-to-input` migration of 0.82.0 rewrites an app's imports of the three names, and of their types, from `@drizztdourden08/tessera` and its `/composites` entry to `@drizztdourden08/brock-input/renderer`; the app needs the input module installed. The import codemod now also sees files that import only from the Tessera root.
- A release step can declare `permissions`, and `workflows.attest` attests release files. A step under `workflows.steps.release.*` takes `permissions` (GitHub permission names with `read`, `write` or `none`) and an `id`; `brock sync` lifts the permissions onto each job that runs the step, merged with the workflow's own, where write wins, and fails on a name or level it does not know. `workflows.attest: { paths, stage }` (`beforePackage` or `afterPackage`) adds `actions/attest-build-provenance`, pinned to a full commit SHA, to the `build-linux` job of the managed `release.yml`, writes each Sigstore bundle beside its file as `<file>.sigstore.json`, and lifts `id-token: write` and `attestations: write` onto that job. An app attests its release files without owning the workflow.
- Data domains under plain Node. `createDataDomains(dataDir, defs)` from `@drizztdourden08/brock-electron/node` returns the same `DataDomains` as `ctx.storage` (with a `DomainFiles` per domain): the same atomic writes, path guards and `usage()` size, for a process with no Electron, such as a headless server. `dataDir` is the folder the domains sit in (the `Data/` folder of an Electron app). The entry still reaches no module of Electron, and a keep test checks the new import graph.
- New `@drizztdourden08/brock-electron/server` entry for apps that run without a window. It never loads Electron. `runServer(start, options?)` resolves the data folder (the `--user-data=` flag, then `BROCK_DATA_DIR`, then systemd `STATE_DIRECTORY`, then `./.user-data`), logs one line per event to stdout (errors to stderr) in the main log format, calls the `stop` that `start` returned on SIGTERM and SIGINT, and writes a heartbeat to `<data>/.brock/server-health.json` every 10 seconds. `start(host)` gets `{ dataDir, args, log, domains }` and returns `{ stop, health? }`; an optional `domains` factory in the options builds the `domains` value from the data folder. The `health` command (`main.mjs health`) reads that file and exits 0 when it is under 30 seconds old and ok, and 1 otherwise, so a container health check or a CI smoke test needs no port. `embedServer(start, ctx, options?)` in `/main` runs the same start function inside the desktop app's main process, with the data folder from `ctx.paths`, the log written through `appendMainLog`, and `stop` called when the app quits.
- `showHeader` in `ScreenMeta`, `LiveMeta` and `LivePage` also takes `'compact'`, which draws the hub page header in Tessera's compact size and still holds `PageActions`; `true` and `false` work as before. `PageHeaderMode` is exported. The lint config turns off `local/hook-file-named-after-hook` for `.live.tsx` and `.live.dev.tsx` files under `src/screens`, so a live file declares its hook and default-exports it without a re-export from a view.
- feat: focus zones for commands `CommandDef` gains `zone`. A zoned command fires only while the focused element sits inside an element marked with `{...commandZone('canvas')}`, and it ranks above a scoped and an unscoped command with the same chord. The same chord in different zones is not a conflict. A command bound to Mod+C, X, V, A or Z already wins over the native Edit menu, since it runs on keydown and prevents the default.
- `input.mapping.list()` entries now carry `source` (`builtin`, `bundled` or `user`), the `mapping` string and `inputCount`, the number of bound inputs the line declares. Main works out the source from the bundled and user database files, so the addon is unchanged.
- A Node secret store for headless apps. `@drizztdourden08/brock-secrets/node` exports `createNodeSecretStore({ dataDir, env?, envPrefix? })`, with the same `canStore`, `set`, `get`, `has`, `list` and `delete` as the Electron store, for a server with no Electron and no OS keychain. The entry never imports `electron`. Secrets live in one JSON file, `<dataDir>/secrets/secrets.json`, written atomically with mode 0600 on posix (on Windows the mode is ignored and the file keeps the folder's ACL). An environment variable `BROCK_SECRET_<KEY>` overrides the file for a key: the name is upper case with each run of characters outside A-Z and 0-9 turned into one `_`, so `api-token` reads `BROCK_SECRET_API_TOKEN`. This store is not encrypted at rest. The Electron store is unchanged.

## Fixes

- Brock 0.81.0 filed the migration documents-access-async under 0.80.0, so an app that upgraded from 0.80.x to 0.81.0 never ran it; it is now filed under 0.81.0. An app already on 0.81.0 runs it with `brock migrate --run documents-access-async`, a new option that runs one migration by id at any version. A keep test now fails when a migration folder is older than the release whose changelog first names it.

# Brock v0.84.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- The server app kind packages. `brock server package [--arch x64,arm64] [--deb]` builds the server, then fills `release/server`: `<prefix>server-linux-<arch>.tar.gz` (the launcher `bin/<id>-server`, a pinned Node binary and `server/main.mjs`, under `<id>/`), a `docker/` build context made from the same tarballs, and with `--deb` a `<prefix>server_<version>_<arch>.deb`. The Node binary comes from nodejs.org, is checked against SHASUMS256.txt, and is cached in `~/.brock/cache/node`; a mismatch stops the build. `--deb` needs `dpkg-deb` and refuses with a clear message on a machine without it (`brock doctor` checks it on Linux). The tarball is written by Brock itself, so the modes are right when it is built on Windows. A server-only app runs the same command as `brock package`. New `server` options in brock.config.ts: `node` (exact Node version, default 24.11.0), `osPackages` (Debian names, the deb `Depends` and the Docker `apt-get install`), `ports` (EXPOSE and the unit description), `image` (default `ghcr.io/<repo owner>/<id>-server`) and `arch` (default `['x64']`; `--arch` overrides it). `brock sync` now keeps `build/server/<id>.service` (system user, `StateDirectory`, restart on failure), `build/server/Dockerfile` (Debian trixie-slim, non-root user, one `/data` volume, `HEALTHCHECK` running `<id>-server health`), `build/server/postinst` and `build/server/prerm`; an optional `build/server/after-install.sh` runs in postinst before the service starts. The unit is sandboxed (`NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`, `PrivateDevices`, `StateDirectoryMode=0750`, `UMask=0027`) and gets `AmbientCapabilities=CAP_NET_BIND_SERVICE` only when `server.ports` lists a port below 1024. A `product.id` that names a system account (root, daemon, www-data, `systemd-*` and the rest of a fixed list) or cannot be an account name is refused by `brock sync`. postinst stops when an account of that name exists and is not the one the package made, joins an existing group of that name, enables and starts the service on a first install only, and `try-restart`s it on an upgrade. The Node archives of the default version are pinned by sha256 in `SERVER_NODE_SHA256` (how to update them is in the brock-build README), the tarball writer refuses absolute and `..` paths, and the deb control fields are checked: the maintainer email and the version must be plain.
- An app can add entries to the title bar View menu. An app menu item keyed `view` with `children` hands them to Tessera 0.54 `WindowTitleBar` as `viewItems`, drawn after Tessera's own View rows with a separator. The item still works as the placement marker for View, and the search palette lists the entries under View. `brock-react` now requires Tessera `^0.54.0`. Tessera 0.54 removes the controller composites and the `stickPosition` and `calibrated` strings. The input module's StickPlot owns those two labels, and the guide registers ControllerLayout, PressedGrid and StickPlot as Brock parts.

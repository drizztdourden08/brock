# Brock v0.85.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- The managed workflows of a server app. An app with `server` in `targets` gets a `server` CI job (build the bundle, start it on a temporary data folder, wait up to 30 seconds for `health`, stop it), a `build-server` release job on ubuntu-24.04 (`brock server package --arch <server.arch> --deb`, uploading the tarball and the .deb as release files and the Docker context as a build artifact), and a `publish-server-image` job after the release job. The image job is the only one with `packages: write`. It uses docker buildx, adds QEMU only when `server.arch` has `arm64`, logs in to ghcr.io with `GITHUB_TOKEN`, and pushes `server.image` (default `ghcr.io/<repo owner>/<id>-server`) tagged with the version, plus `latest` only when the release runs with `set_latest`. `server.image` must live under `ghcr.io/`. The new Docker actions are pinned to full commit SHAs (setup-qemu-action v4.4.0, setup-buildx-action v4.4.1, login-action v4.6.0, build-push-action v7.4.0). An app whose only target is `server` has no `review` job. `Platform` gains `publishJob`, a job that needs the release job, and app steps can name the new jobs (`server` in CI, `build-server` in the release). A desktop-only app keeps byte-identical workflows.
- `brock-react` now requires Tessera `^0.55.0`. The release adds ContextMenu, AnchorPicker, VirtualList, `useMarqueeSelect` and SegmentedControl icons that take any node. It has no MIGRATION entry, and Brock needed no code change for it.

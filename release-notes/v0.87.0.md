# Brock v0.87.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- Set up the Linux test job of the managed ci.yml. `workflows.testEnv` in `brock.config.ts` takes `linuxPackages`, Debian package names that the `quality` job installs with `apt-get install -y --no-install-recommends` before the build (checked with the pattern `server.osPackages` uses), and `userNamespaces: true`, which adds the step that sets `kernel.apparmor_restrict_unprivileged_userns=0` so a test can run a real bubblewrap sandbox. The step is the one the `review` job runs, now shared. It is a sibling of `workflows.ci` because that key is the `managed` or `own` mode. An app that sets neither option gets the same ci.yml as before. `docs/architecture.md` says that `server.osPackages: ['bubblewrap']` already reaches the `.deb` `Depends` and the Docker image, and lists the `docker run` and compose security options a container running bubblewrap needs.
- Docked toolbars by convention, on Tessera `^0.56.0`. An app puts a toolbar in `src/toolbars/<id>.toolbar.tsx`, default-exporting `defineToolbar({ id, label, defaultSide, hiddenByDefault?, render(slot) })`; `slot` carries the orientation, the grip `handle` and the `side`. `brock sync` lists the files in `.brock/toolbars.ts` as `appToolbars`, `brock structure` accepts and checks the folder, and `RendererModule.toolbars` adds a module's toolbars. `BrockApp` takes `toolbars` and, when at least one is registered, wraps the widget host in Tessera's `ToolbarDock` inside `brock-app__stage`. An app with no toolbars is unchanged. The layout is saved per profile as its own `toolbarLayout` key in `ui-views.json` beside `widgetLayout`, loaded with `migrateToolbarLayout`, and defaults to `createToolbarLayout`. `useToolbarMenuEntries()` adds a Toolbars sub-menu to Widgets, with its own Reset toolbars entry; Reset layout still resets widgets only. The `toolbar-files` migration (0.87.0) adds `toolbars={appToolbars}` and its import to `src/main.tsx`. The lint stack allows the default export in `src/toolbars/*.toolbar.tsx`.
- When `workflows.publish` is set, `brock sync` also writes a managed `publish-packages.yml` that publishes the listed packages on `workflow_dispatch`, with an optional `packages` input for a comma-separated subset. It shares its steps with the `publish-packages` job of `release.yml`, needs no app build job, and refuses a folder that is not in `workflows.publish`. `brock check` compares the new file, and an app without `workflows.publish` gets no file.
- Add `server.optionalAddons: string[]` to `brock.config.ts`, a list of package names. For a `.node` require, or a `bindings`, `node-gyp-build` or `prebuild-install` load, inside a listed package, `brock server build` replaces the addon with a module that throws when it loads, so the package's own try/catch runs and the bundle carries no binary (ssh2 and cpu-features work this way). An addon in the app's own code or in an unlisted package is still refused, and the error now names the package and points to `server.optionalAddons`. `@drizztdourden08/brock-electron/server` also exports `resolveDataDir(argv, env, cwd)`, the rule `runServer` uses for the data folder (`--user-data=`, `BROCK_DATA_DIR`, `STATE_DIRECTORY`, then `./.user-data`); `runServer` calls the same function.
- A helper can now start the app and call ask channels. `appLaunch({ background? })` from `brock-electron/main` returns `{ command, args, env }` for the current app, packaged or in development, with the identity flags of the launch. The bridge writes it to `launch-<discovery file name>` beside the discovery file each time it opens, and `readAppLaunch` and `startApp` from `brock-electron/bridge` read it under the same private-file checks and start the app, with `--background` on request. `relayAsk(bridge, CHANNEL, { window, timeoutMs?, validate? })` exposes an ask channel as a bridge route, so `bridge.request` accepts ask channels and returns the renderer's answer; `validate` is required, at most 8 requests wait per route (code `busy`), and failures reach the helper as fixed `no-window`, `timeout` and `closed` errors or as `the request failed`. `readAppLaunch` refuses a launch file with a non-empty `env` or unknown arguments, and `startApp` checks the executable exists and drops `ELECTRON_RUN_AS_NODE` and `NODE_OPTIONS` in any case. `--instance` and `--profile` no longer stop `--background` from counting, so a background launch works for a named instance. `channelApi` no longer throws on a channel set that holds ask channels, which the preload never maps. `brock-core` exports `BACKGROUND_FLAG`, and `IDENTITY_FLAGS` from `/automation`.
- `ctx.window.show()` now brings the window of a hidden automation launch on screen, at its saved bounds or centred on the primary work area, and `ctx.dialogs.confirm({ title, message, detail?, confirmLabel?, cancelLabel? })` asks a native yes or no question from main code while the app window is hidden. On an automation launch confirm shows nothing and resolves false.
- `brock-react` now requires Tessera `^0.56.0`, and the lockfile resolves 0.56.1, which fixes the double fold handle of ListDetailLayout. The release adds ToolbarDock, `useToolbarLayout` and `toolbarMenuGroups`, tooltips on segmented controls and toggle groups, and crisp pixel icons. Its MIGRATION notes have no entry that concerns Brock, and the bump itself needed no code change.

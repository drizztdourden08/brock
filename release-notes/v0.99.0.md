# Brock v0.99.0

One paragraph for the people who use Brock: what this release changes for them.

## Changes

- A widget can carry a `dockWeight`, its relative height in a stack (1 when unset). A layout preset row with no entry in `sizes` takes the largest `dockWeight` among its widgets, so a definition can ask for a taller row. The `sizes` of a preset still win, and a saved layout still wins over the default. A widget opened later with `defaultSide` joins its edge stack through Tessera, which evens the stack out, so `dockWeight` does not reach it yet.

## Fixes

- @drizztdourden08/brock-build@0.99.0
- @drizztdourden08/brock-core@0.99.0
- Brock builds on Tessera 0.65. A toolbar end handle dragged past its lane end takes the corner from the lanes it crosses, and one more arrow press at the lane end does the same from the keyboard. A dropped toolbar lands at the pointer, snaps to its neighbours and pushes them along. In keyboard pick mode, PageUp and PageDown step through the slots of a lane. The saved layout keeps its v2 shape, so no script is needed. - @drizztdourden08/brock-core@0.99.0
- `worktree refresh` no longer refuses a fresh worktree because of the files the setup writes itself. Untracked `CLAUDE.md`, `.ai-config.json`, `.mcp.json`, `.brock-port-slot` and `.user-data/` do not count as local changes, for `refresh`, `finish`, `remove` and the dirty warning of `pr push`. A tracked file with changes, or any other untracked file, still blocks.
- `resolveDeviceFromEntry` and `recallControllerSdlType` are now exported from the root entry `@drizztdourden08/brock-input` too, so code with no UI, such as a worker, can use them without pulling React and Tessera through the renderer entry. The renderer entry keeps them.
